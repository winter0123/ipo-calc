# 작업 로그: 비용 기록 (cost-recording, Epic 9)

## 2026-09-21 — Master 결정 사항 (Phase 0 spec 작성 전 스코프 정정)

`docs/research/cost-recording.md`는 이전 3개 Epic(6/7/8)과 달리 실시간 처리
전제 오류는 없다(사용자 입력 중심 접근이 이미 올바르게 결론남). 다만
**Epic 8(Sale)과의 책임 경계가 겹치는 문제**가 있다: Epic 8에서 이미
`Sale.fee`(수수료), `Sale.tax`(세금), `Sale.otherCost`(기타비용) 필드로
매도 시점 비용을 기록하도록 설계했는데([[sale-management]] D-SL-007),
Epic 9 조사 문서도 동일하게 "매도 수수료·세금·기타 비용"을 기록 대상으로
잡고 있어 중복 설계 위험이 있다. work-plan 15장의 수익 공식
(`매도금액 - 취득 관련 비용 - 매도 수수료 - 세금 - 기타 비용 = 순수익`)을
보면 "취득 관련 비용"이 매도 수수료/세금/기타비용과는 별개 항목으로
구분되어 있으므로, 이 구분을 Epic 8/9의 책임 경계로 삼는다.

### D-C-001: Epic 9(Cost)는 "취득 관련 비용"만 다룬다 — 매도 비용과 중복 설계 금지
매도 시점 비용(수수료/세금/기타비용)은 이미 Epic 8의 `Sale.fee/tax/
otherCost` 필드로 기록되므로 Epic 9에서 다시 설계하지 않는다. Epic 9의
Cost 엔티티는 **청약/취득 단계에서 발생하는 비용**(예: 청약 수수료, 계좌
개설비, 이체 수수료 등)만을 대상으로 하며, **Subscription을 참조(N:1)**
한다.

### D-C-002: Subscription 1건당 Cost는 여러 건 가능 (1:N, 유니크 제약 없음)
하나의 청약에 여러 항목의 취득 비용이 있을 수 있다(예: 청약 수수료 +
계좌 관리비를 별도 항목으로 기록). 비용 종류(costType)는 자유 텍스트로
기록하며 Enum 제약을 두지 않는다 — 수수료/세금 정책이 자주 바뀌고
증권사마다 다르므로(조사 결론 그대로 반영).

### D-C-003: 수정은 시점 제약 없이 전체 허용, 별도 변경 이력 테이블 불필요
[[sale-management]] D-SL-003/D-SL-005와 동일 원칙: 사후 기록 서비스이므로
모든 필드를 자유롭게 수정할 수 있고, 별도의 변경 이력 테이블이나 감사
로그 테이블은 MVP 범위 밖이다(created_at/updated_at으로 충분).

### D-C-004: 삭제는 논리 삭제만 (ACTIVE/CANCELLED)
다른 금융 기록 엔티티와 동일하게 물리 삭제 금지, status(ACTIVE/CANCELLED)
+ deletedAt으로 논리 삭제만 적용한다.

### D-C-005: 금액 검증만 수행, 세율/수수료 자동 계산 로직 절대 금지
조사 문서의 핵심 결론(사용자 입력 그대로 기록, AI가 임의로 세율/수수료를
추정하지 않음)을 그대로 따른다. `amount >= 0`만 검증하고, 어떤 형태로든
세율이나 수수료를 자동 계산하는 로직은 설계·구현하지 않는다.

### D-C-006: 통화는 원화 단일 지원 (다중 통화 필드 불필요)
MVP 범위에서 원화만 다루므로 별도 통화(currency) 필드는 두지 않는다.

이 결정들은 `docs/spec/cost-recording.md` / `docs/architecture/cost-recording.md`
작성 태스크 지시에 반영되었다.
