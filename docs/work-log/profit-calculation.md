# 작업 로그: 수익 계산 (profit-calculation, Epic 10)

## 2026-09-21 — Master 결정 사항 (Phase 0 spec 작성 전 스코프 정정)

`docs/research/profit-calculation.md`는 세금 자동계산을 피하고 조사 부족
영역을 정직하게 표시한 점은 좋으나(원칙 자체는 유지한다), 결론에서
제안한 **`CalculationTrace` 엔티티**(출처 구분 5종, 적용 근거, 정책
버전 관리, "누가/언제/왜" 수정 이력)는 Epic 8/9에서 확립한 원칙
([[sale-management]] D-SL-005, [[cost-recording]] D-C-003: "별도의
변경 이력 테이블, 감사 로그 테이블, 아카이브 전략은 MVP 범위 밖")과
정면으로 배치되는 과도한 설계다. 이 프로젝트는 회계감사 시스템이
아니라 개인용 투자 기록 도우미이므로, 세금/취득가액에 대한 신중함은
"자동 계산·추정 금지" 원칙으로 충분히 확보되며 별도 이력 인프라가
필요하지 않다.

### D-P-001: Profit은 저장하지 않는 파생값(on-demand 계산)으로 설계한다
순수익은 Sale과 Cost 레코드를 조회 시점에 조합해 계산하는 **파생값**이며,
별도의 Profit 테이블이나 CalculationTrace 엔티티를 두지 않는다. 계산에
쓰인 근거는 이미 Sale/Cost 각 레코드 자체(어떤 매도/비용 기록을 참조했는지)
로 충분히 추적 가능하다 — Epic 8/9에서 이미 각 레코드가 `created_at`/
`updated_at`을 가지고 있으므로 별도 출처 메타데이터 테이블은 불필요하다.

### D-P-002: 세금은 Sale.tax를 그대로 사용, 이 Epic에서 세율/공제 계산 안 함
"세후 순수익"이라는 표현을 쓰더라도 이는 단지 `Sale.tax`(사용자가 입력한
실제 납부/공제 세액)를 차감한 값일 뿐이며, 별도의 세법 정책 엔진이나
세율 테이블을 만들지 않는다(조사 결론 "세율을 코드 상수에 고정하지
않는다"를 그대로 따름 — 애초에 세율 계산 자체를 하지 않으므로 이 원칙이
자동으로 지켜진다).

### D-P-003: 취득가액/비용 안분은 단순 비례식, 잔차는 그대로 허용
분할 매도 시 취득가액 안분: `해당 매도 취득가액 = Allocation.allocationPrice
× Sale.quantity` (allocationPrice가 없으면 참조 IPO의 fixedPrice 사용).
취득 비용(Cost) 안분도 동일 비율로 계산한다. 각 매도 건은 독립적으로
반올림하며, 분할 매도 누적 시 합계가 배정금액과 원 단위로 어긋나는 잔차는
그대로 허용한다(정밀 회계 시스템이 아닌 개인 기록 도구이므로 원 단위
오차는 감내 가능 — 조사 문서의 "잔차 처리 표준 방식" 불확실 항목은
정책적으로 이렇게 단순화해 해소한다).

### D-P-004: 연환산 수익률은 이 Epic 범위 밖 (조사 결론 그대로)
XIRR 등 연환산 수익률 계산은 하지 않는다. 세전/세후 실현 손익(금액)까지만
계산한다.

### D-P-005: 취득가액 기준은 "배정금액" 단일 기준을 MVP 기본값으로 채택
조사 문서는 취득가액 산정 기준(청약금액 vs 배정금액 vs 환불후 순액)의
세법상 공식을 확인하지 못해 "사용자/정책 선택"으로 열어두었으나, MVP에서
선택 UI까지 만드는 것은 범위 밖이다. Master는 가장 상식적인 단일 기준인
**배정금액(Allocation.allocatedQuantity × allocationPrice)**을 기본
취득가액으로 채택한다. 청약금액/증거금/환불금액은 Subscription/Cost에
이미 별도 필드로 보존되어 있으므로 손실되지 않으며, 세법 공식이 추후
확인되면 이 계산 로직만 교체하면 된다(설계 결합도를 낮게 유지).

### D-P-006: Profit 계산 API는 매도(Sale) 단위로 조회하는 GET 엔드포인트로 제공
쓰기 API가 아니라 읽기 전용 계산 API다 — 특정 Sale 또는 Investor 단위로
"세전순수익/세후순수익" 값을 계산해 반환하며, 데이터베이스에 결과를
저장하지 않는다(D-P-001).

이 결정들은 `docs/spec/profit-calculation.md` /
`docs/architecture/profit-calculation.md` 작성 태스크 지시에 반영되었다.
