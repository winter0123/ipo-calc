# IPO 데이터 조사 연구 문서

## 조사 목적
공모주 기준정보 관리를 위한 IPO 도메인 설계에 필요한 필드 확인, 공식·공개 데이터 제공처 조사, 외부 데이터 수집 가능성 분석, 자동 수집 불가 시 대안 탐색, 안정적 식별자 설계 방안 연구

## 조사 대상
- IPO 도메인에 필요한 필드
- 한국 공모주 일정을 제공하는 공식/공개 데이터 출처
- 해당 출처들의 API 호출 제한 및 상업적 이용 가능 여부
- 자동 수집이 불가능한 경우의 대안 방안
- 동일 공모주가 여러 투자자/계좌로부터 참조되는 구조에서의 안정적 식별자 설계

- docs/roadmap.md (Epic 5: 공모주 기준정보 관리) - 확인일: 2026-09-20

## 확인한 내용

### 1. IPO 도메인에 필요한 필드
work-plan.md 10장에 따르면 IPO는 공모주 자체의 정보를 나타내며, 다음과 같은 필드가 제시됨:
- 기업명
- 공모주명  
- 공모가
- 청약 시작일
- 청약 종료일
- 상장일

추가로 고려할 수 있는 필드로는 work-plan.md에서 언급된 바와 같이 공모주식수, 희망공모가 밴드, 확정공모가 시점 등이 있지만, 정확한 필드 목록은 설계 단계에서 확정해야 함.

### 2. 한국 공모주 일정을 공식/공개적으로 제공하는 데이터 출처 후보
work-plan.md 24장에 제시된 조사 프로세스에 따라 확인 가능한 출처 후보:
- 한국거래소(KRX): 국내 주식시장 운영기관으로 IPO 정보 제공 가능성 높음
- 금융감독원 전자공시(DART): 증권신고서 등 법정 공시자료 제공
- 38커뮤니케이션: 금융 정보 제공 사이트로서 IPO 일정 정보 제공 가능성 있음

다만, 실제 이용 가능 여부, API 제공 현황, 이용약관 확인은 추가 조사가 필요함.

### 3. 출처들의 API 호출 제한 및 상업적 이용 가능 여부
work-plan.md 24장에 명시된 조사 항목이지만, 현재 세션에서는 실제 사이트 접속을 통한 구체적인 확인 불가. 따라서 다음 사항은 확인되지 않음:
- API 존재 여부 및 상세 스펙
- 호출 제한 정책 (rate limit 등)
- 상업적 이용 가능 여부 및 조건
- 데이터 신뢰성 및 갱신 기준

### 4. 자동 수집이 현재 단계(MVP)에서 불가능하거나 검증되지 않았다고 가정할 때의 대안
work-plan.md 25장에 명시된 대안 방안:
- 사용자 직접 입력
- 공식 API 사용 (가능한 경우)
- CSV 가져오기
- 관리자 데이터 등록
- 다른 합법적인 데이터 공급원

MVP 단계에서는 개발 복잡성 및 법적 리스크 최소화를 위해 수동 입력 또는 CSV 가져오기 방식이 적합할 것으로 판단되나, 최종 결정은 추가 조사 후 필요.

### 5. 동일 공모주가 여러 투자자/계좌로부터 참조되는 구조에서의 안정적 식별자 설계
work-plan.md 38-39장에서 Account-Investor-SecuritiesAccount-IPO-Subscription 구조를 확인할 수 있음. IPO는 여러 Subscription이 참조할 수 있는 구조로 설계해야 함.

예시 구조:
```
IPO A
  ├── Subscription 1 (투자자 A, 계좌 X)
  ├── Subscription 2 (투자자 B, 계좌 Y)
  ├── Subscription 3 (투자자 A, 계좌 Y)
  └── Subscription 4 (투자자 C, 계좌 Z)
```

안정적 식별자로는 종목코드(6자리 숫자) 또는 시스템 내부 ID 사용을 고려할 수 있으나, 정확한 설계는 아키텍처 단계에서 확정해야 함.

## 제약사항
1. 외부 데이터 자동 수집을 위한 구체적인 API 정보 확인 불가 (실제 사이트 접속 및 이용약관 확인이 필요)
2. 데이터 제공처의 상업적 이용 가능 여부 및 조건 미확인
3. 특정 연동 방식이나 API 확정 금지 (작업 지침)
4. 금융 데이터의 특성상 정확성 및 신뢰성 검증이 필수적이나 현재 세션에서는 제한적 조사만 가능

## 불확실한 점
1. 한국거래소(KRX)의 IPO 데이터 제공 API 존재 여부 및 상세 스펙
2. 금융감독원 DART의 IPO 관련 공시자료 자동 수집 가능성 및 이용약관
3. 38커뮤니케이션 등의 사이트에서 제공하는 IPO 데이터의 정확성 및 업데이트 주기
4. 각 출처별 호출 제한 정책 및 상업적 이용 허가 조건
5. 데이터 제공처별 제공 필드의 상세 항목 및 형식
6. 자동 수집이 기술적/법적으로 불가능한 경우의 구체적 판단 기준

## 개발에 미치는 영향
1. IPO 도메인 설계 시 work-plan.md 10장에 제시된 기본 필드(기업명, 공모주명, 공모가, 청약 시작일/종료일, 상장일)를 반드시 포함해야 함
2. 외부 데이터 자동 수집을 위한 기능을 설계할 경우, 현재 단계에서는 구현을 보류하고 수동 입력/CSV 가져오기 옵션을 우선 제공해야 함
3. IPO 엔티티는 여러 Subscription이 참조할 수 있도록 설계해야 하며, 안정적 식별자 시스템을 마련해야 함
4. 향후 외부 데이터 수집 기능을 구현하기 전에 별도 조사 Task를 통해 이용약관, 기술적 가능성, 비용 등을 확인해야 함
5. MVP 단계에서는 사용자 직접 입력 또는 CSV 가져오기 방식으로 시작하여, 추후 외부 API 연동 가능성을 재검토하는 것이 적절함

## 결론
IPO 기준정보 관리를 위한 MVP에서는 사용자 직접 입력 및 CSV 가져오기 방식을 중심으로 기능을 구현하는 것이 적절하다. work-plan.md에 명시된 기본 필드(기업명, 공모주명, 공모가, 청약 시작일/종료일, 상장일)를 기반으로 IPO 도메인을 설계하고, 외부 데이터 자동 수집은 법적/기술적 검증이 완료된 이후 단계에서 고려해야 한다. 여러 투자자/계좌가 동일한 IPO를 참조할 수 있는 구조를 지원하기 위해 IPO 엔티티에 안정적 식별자 시스템을 마련해야 한다.
