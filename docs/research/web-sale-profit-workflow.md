# 웹 매도-수익 워크플로우 조사 문서

## 조사 목적
Epic 15 `web-sale-profit-workflow` 구현에 앞서, 배정 결과에서 매도 기록 → 비용 기록 → 수익 계산까지의 전체 워크플로우에서 금액·수량 입력 방식, 오류 표현, 수익 결과 설명 방식, 부분 매도·미매도 상태 표현, 접근성·반응형 기준, 그리고 주요 흐름의 E2E 테스트 범위를 조사하여 사용자 중심의 안전한 금융 데이터 관리 기반을 마련한다.

## 확인한 내용

### 1. 금액·수량 입력과 오류 표현은 어떻게 해야 하는가 (매도/비용 기록 화면)?
매도 및 비용 기록 시 금액과 수량 입력에 대해서는 데이터 무결성 검증이 필수이다. 매도 수량은 0 이상이어야 하며, 누적 매도 수량은 배정 수량을 초과해서는 안 된다. 비용 금액 역시 0 이상이어야 한다. 이들 검증은 서비스 계층에서 트랜잭션 내에서 수행되어야 한다. 오류 표현에 있어서는 금융 기록의 특성상 단순한 CRUD 처리 대신 논리 삭제 또는 수정 이력 관리 방식을 채택해야 하며, 사용자 입력 오류 시에는 구체적인 필드와 오류 이유를 명확히 표시하여 사용자가 수정할 수 있도록 해야 한다.

### 2. 수익 결과의 설명 방식은 어떻게 해야 하는가 (계산 근거를 어떻게 보여줄지)?
수익 결과는 모든 입력값과 결과값에 출처 메타데이터를 필수로 저장하여 설명해야 한다. 메타데이터에는 값의 종류(취득가액, 매도금액, 수수료, 세금, 기타비용 등), 금액(원 단위 정수), 발생일시, 출처 구분(USER_INPUT | POLICY_VALUE | BROKER_STATEMENT | TAX_AUTHORITY | CALCULATED), 적용 근거(세법 조문 번호, 증권사 공지 URL, 사용자 메모 등), 그리고 계산 시 사용된 정책 버전/일자가 포함되어야 한다. 또한 수익 계산 결과(세전순수익, 세후순수익 등)도 동일 구조로 저장하며, 어떤 입력값·정책값으로 산출됐는지 CalculationTrace 엔티티로 연결하여 완전한 추적성을 확보해야 한다.

### 3. 부분 매도·미매도 상태 표현은 어떻게 해야 하는가?
잔여 수량(배정수량 - Σ(매도수량))을 기반으로 투자자 뷰에서 일부 매도/전량 매도/보유 중 상태를 표현해야 한다. 매도 자체가 완료된 행위이므로 별도 상태 필드보다 매도 일시와 수량으로 상태를 유추하는 것이 적절하다. 분할 매도의 경우 매도 순서는 비즈니스적으로 의미 있으므로, 매도 일시 기준 순서 자동 정렬 또는 명시적인 순서 번호 필드를 사용하여 순서를 표현해야 한다.

### 4. 접근성·반응형 기준은 무엇을 따라야 하는가?
조사 대상 문서(sale-management/cost-recording/profit-calculation)에는 접근성·반응형 기준이 명시되지 않았다. 다만 docs/research/web-account-setup.md, docs/research/web-subscription-workflow.md 등 다른 프론트엔드 Epic 조사 문서에서 이미 채택된 기준을 그대로 따르는 것이 프로젝트 전체 일관성 측면에서 적절하다: WCAG 2.1 AA 수준(색 대비 4.5:1 이상, 키보드 내비게이션, ARIA 라벨), 모바일 우선 반응형 설계(최소 320px, 브레이크포인트 640/768/1024px). 금융 기록 화면이므로 수익 계산 결과를 보여주는 표/카드는 작은 화면에서 가로 스크롤 또는 카드 전환으로 처리해야 한다.

### 5. 주요 흐름(배정→매도 기록→비용 기록→수익 확인)의 E2E 테스트 범위는 어디까지인가?
주요 흐름의 E2E 테스트 범위는 배정 → 매도 기록 → 비용 기록 → 수익 계산까지의 전체 워크플로우를 포함해야 한다. 각 단계에서의 데이터 무결성 검증(매도 수량 검증, 비용 금액 검증, 누적 매도 수량 ≤ 배정 수량 검증 등)을 테스트해야 하며, 매도 기록과 비용 기록 사이의 연동, 비용 합계가 수익 계산에 올바르게 반영되는지 등의 인터페이스도 테스트해야 한다. 또한 상태 전이 테스트, 중복 방지 테스트, 동시성 테스트 등을 포괄해야 한다.

## 결론
웹 매도-수익 워크플로우는 데이터 무결성 검증과 출처 메타데이터 기반 추적성이 핵심이다. 매도 및 비용 입력 시 금액과 수량에 대한 검증 로직을 구현하고, 오류 발생 시 사용자가 수정할 수 있도록 구체적인 피드백을 제공해야 한다. 수익 계산 결과는 모든 입력값과 정책 정보와 연결된 메타데이터를 저장하여 계산 과정을 투명하게 보여줘야 한다. 부분 매도 상태는 잔여 수량을 기반으로 표현하며, 매도 순서는 비즈니스적으로 의미 있는 방식으로 관리해야 한다. 주요 흐름의 E2E 테스트는 각 단계의 데이터 무결성 검증과 단계 간 연동을 포괄해야 한다.
