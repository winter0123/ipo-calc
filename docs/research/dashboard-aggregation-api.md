# 대시보드 집계 API (dashboard-aggregation-api) 조사 문서

## 조사 목적
Epic 12 `dashboard-aggregation-api` 구현에 앞서, 전체·투자자별·증권사별·기간별 투자금, 수익, 수익률, 참여 건수를 일관된 기준으로 집계하는 API의 설계 원칙을 조사한다. 특히 총투자금·총수익·총수익률의 정확한 정의, 부분 매도와 미매도 주식의 집계 처리, 기간별 귀속 기준, 증권사·투자자별 분모 통일, 집계 결과의 반올림과 일관성 검증 방법을 중점적으로 조사한다.

## 확인한 내용 (1~5번 질문 각각에 대한 답)

### 1. 총투자금·총수익·총수익률의 정확한 정의는 무엇인가?
- **총투자금**: 수익 계산 조사문서에 따르면 단일 값으로 정의할 수 없으며, 청약금액, 증거금, 환불금액, 배정수량×공모가(배정금액), 청약·배정 단계 발생 수수료·세금을 모두 별도 필드로 보존하고 적용 기준을 사용자 또는 정책 선택에 맡긴다. 따라서 대시보드 집계에서는 이들 항목 중 선택된 기준을 합산한 값을 총투자금으로 정의해야 한다.
- **총수익**: 수익 계산 조사문서에 따라 각 매도 건의 실현수익(`매도금액 - 취득 관련 비용 - 매도 수수료 - 세금 - 기타 비용`)의 합으로 정의한다. 취득 관련 비용은 분할 매도 시 배정 수량 대비 매도 수량 비율로 안분 배분한다.
- **총수익률**: 총수익 / 총투자금으로 계산되나, 총투자금의 정의에 따라 달라질 수 있다. 대시보드에서는 선택된 투자금 기준에 기초한 수익률을 일관되게 제공해야 한다.

### 2. 부분 매도와 미매도 주식은 집계에서 어떻게 처리해야 하는가?
- **부분 매도**: 수익 계산 조사문서에서 분할 매도 시 취득 관련 금액과 비용을 배정 수량 대비 매도 수량 비율로 안분 배분한다고 명시하였다. 따라서 대시보드 집계에서도 각 매도 건에 대응하는 취득가액과 비용을 안분하여 집계에 반영해야 한다.
- **미매도 주식**: 투자 내역 조회 API 조사문서에서 미매도 수량은 `배정수량 - Σ(매도수량)`로 계산하고, 투자 내역 조회 API에서는 각 배정 레코드에 미매도 수량을 포함하여 표시한다고 명시하였다. 대시보드 집계에서는 미매도 주식은 아직 실현되지 않은 취득가액으로 처리하되, 도로맵에서 대시보드 집계 API의 제외 범위에 "미확정 평가손익의 실시간 표시"가 명시되어 있으므로, 대시보드에서는 실현수익만을 대상으로 집계하고 미매도 주식은 별도 미실현손익 지표로 처리하는 것을 검토해야 한다.

### 3. 기간별 귀속 기준(월별/연도별)은 무엇으로 삼아야 하는가?
- 투자 내역 조회 API 조사문서에서 "투자 내역 조회 API의 경우 사용자가 주로 보는 것은 '내가 언제 어떤 주식을 샀고 팔았는가'이므로 매도 일시를 기본 기준으로 하되, 청약일·배정일도 필터 옵션으로 제공하는 방식이 적절함"이라고 명시하였다.
- 따라서 대시보드 집계에서는 **매도 일시를 기간별 귀속 기준으로** 삼는 것이 적절하다. 월별 집계는 매도 일시의 년-월 단위로, 연도별 집계는 매도 일시의 년 단위로 그룹화한다.

### 4. 증권사·투자자별 분모를 어떻게 통일해야 하는가?
- 투자 내역 조회 API 조사문서에서 "투자자 → 증권사 → 계좌 → 공모주 순의 계층적 집계 구조를 지원해야 함"이라고 명시하였다.
- 따라서 대시보드 집계에서는 다음과 같이 분모를 통일해야 한다:
  - **투자자별 집계**: 한 계정 내 여러 투자자(본인·가족 등)를 구분하여 집계한다.
  - **증권사별 집계**: 동일한 증권사의 여러 계좌를 합산하여 집계한다 (증권사 기준정보 관리에서 식별자 사용).
  - 통일 원칙: 모든 집계에서 동일한 기준(매도 일시 기간 귀속, 실현수익 기준)을 적용하여 투자자별과 증권사별 결과 간 일관성을 유지한다.

### 5. 집계 결과의 반올림과 일관성 검증 방법은 무엇인가?
- 수익 계산 조사문서에서 금액은 **원(원화) 단위 정수**로 저장(소수점 없음), 안분 계산 등 불가피한 소수 발생 시 **반올림(사사오입)** 후 원 단위 정수로 확정, 안분 잔차(분할 매도 누적 시 합계 불일치)는 **마지막 매도 건에 흡수**하거나 별도 잔차 필드에 기록한다고 명시하였다.
- 따라서 대시보드 집계에서도 동일한 반올림 규칙을 적용해야 한다.
- 일관성 검증 방법:
  1. 집계 결과의 합이 개별 항목들의 합과 일치하는지 검증 (안분 잔차 처리 고려)
  2. 기간별 집계(월별/연도)의 합이 전체 집계와 일치하는지 검증
  3. 투자자별 집계의 합이 전체 집계와 일치하는지 검증
  4. 증권사별 집계의 합이 전체 집계와 일치하는지 검증
  5. 모든 금액 값에 출처 메타데이터(값의 종류, 금액, 발생일시, 출처 구분, 적용 근거, 계산 시 사용된 정책 버전/일자)를 저장하여 추적 가능성을 확보한다.

## 제약사항
1. **데이터 일관성**: 집계 시점의 일관된 스냅샷 제공 필요 (동시성 이슈 고려)
2. **성능 요구사항**: 대용량 데이터셋에서도 응답 시간 보장 필요
3. **보안**: 계정 간 데이터 완전 격리 필수 (인증·인가 기반)
4. **금융 데이터 특성**: 추정치 대신 실제 기록된 값만 제공
5. **의존성**: Epic 10 `profit-calculation`과 Epic 11 `investment-query-api`가 선행되어야 함
6. **제외 범위**: 도로맵에서 대시보드 집계 API의 제외 범위에 "프론트엔드 차트 구현, 실시간 주가, 고급 포트폴리오 분석, 자동 투자 추천, 미확정 평가손익의 실시간 표시"가 명시됨

## 불확실한 점
| # | 불확실한 점 | 영향도 | 비고 |
|---|-------------|--------|------|
| 1 | 총투자금의 정확한 정의(청약금액 vs 배정금액 vs 증거금 등 중 어떤 기준을 사용할지) | 높음 | profit-calculation에서 공식 확인되지 않아 사용자 선택 옵션 제공 필요 |

| 3 | 기간별 귀속 기준의 최종 확정(매도 일시 기준이 적절한지) | 낮음 | 투자 내역 조회 API에서 매도 일시 기본 채택 시 따름 |

| 5 | 금융투자소득세 2026-2027년 적용 여부와 세금 계산식 영향 | 높음 | profit-calculation-tax.md에서 미확인 |

## 결론
대시보드 집계 API는 매도 일시를 기간별 귀속 기준으로 삼아 총투자금(선택된 투자금 기준 합산), 총수익(실현수익의 합), 총수익률(총수익/총투자금)을 투자자별·증권사별·월별·연도별로 일관되게 제공해야 한다. 부분 매도는 취득가액과 비용을 수량 비례로 안분하여 처리하고, 미매도 주식은 실현수익 집계에서 제외하되 별도 미실현손익 지표로 제공하는 것을 검토해야 한다. 모든 금액은 원 단위 정수 저장·사사오입 반올림·안분 잔차 흡수 원칙을 적용하고, 집계 결과의 합 개별 항목 합 일치성 검증 및 출처 메타데이터 저장을 통해 추적성과 일관성을 확보해야 한다.
