# 웹 투자 내역 대시보드 (web-inquiry-dashboard) 조사 문서

## 조사 목적
Epic 16 `web-inquiry-dashboard` 구현에 앞서, 투자 내역 조회 API(Epic 11)와 대시보드 집계 API(Epic 12)의 결과를 바탕으로 사용자의 투자 기록을 시각적으로 표현하는 웹 대시보드의 설계 원칙을 조사한다. 특히 지표 화면 표현, 기간 선택 방식, 필터 조합 처리, 빈 결과 처리, 접근성·반응형 기준, 주요 사용자 흐름의 E2E 검증 범위를 중점적으로 조사한다.

## 확인한 내용 (1~4번 질문 각각에 대한 답)

### 1. 대시보드 지표의 화면 표현과 기간 선택 방식은 어떻게 해야 하는가?
- 대시보드 집계 API 조사문서에 따르면 표시해야 할 핵심 지표는 **총투자금(선택된 투자금 기준 합산), 총수익(실현수익의 합), 총수익률(총수익/총투자금)** 이다
- 투자 내역 조회 API 및 대시보드 집계 API 조사문서 모두에서 **매도 일시를 기간 필터의 기본 기준으로** 삼는 것이 적절하다고 명시되어 있음
- 기간 선택 방식은 **투자자별, 증권사별, 월별, 연별 집계**를 지원해야 하며, 매도 일시를 기준으로 년-월 단위(월별) 또는 년 단위(연별)로 그룹화하는 방식으로 구현해야 함
- 지표 화면 표현은 카드 형태의 위젯으로 구성하고, 각 지표에 대한 라벨과 값, 전일 대비 변화율(선택적)을 함께 표시하는 방식이 적절함

### 2. 필터 조합과 빈 결과 처리는 어떻게 해야 하는가?
- 투자 내역 조회 API 조사문서에서 **투자자 → 증권사 → 계좌 → 공모주 순의 계층적 필터 구조**를 지원해야 한다고 명시되어 있음
- 필터 조합은 **AND 조건으로 작동**하도록 구현하고, 선택된 필터에 해당하는 데이터가 없을 때는 빈 결과를 적절히 처리해야 함
- 빈 결과 처리 방식은:
  * 데이터가 없을 때는 차트 대신 "해당 조건에 해당하는 투자 기록이 없습니다" 라는 안내 메시지 표시
  * 필터 조건을 수정할 수 있는 버튼이나 링크 제공하여 사용자가 쉽게 조건을 조정할 수 있도록 함
  * 차트나 지표 영역에는 0 값 또는 빈 상태를 시각적으로 표시하여 데이터 부재 상태를 명확히 인지시킴

### 3. 접근성·반응형 기준은 무엇을 따라야 하는가?
- 접근성 기준은 **WCAG 2.1 AA** 수준을 준수해야 함 (화면 대비 비율, 키보드 네비게이션, 스크린 리더 지원 등)
- 반응형 기준은 **모바일 우선** 접근법을 따라야 하며, 다양한 화면 크기(모바일, 태블릿, 데스크톱)에서 정상 동작 보장
- 구체적 구현 사항:
  * 모든 인터랙티브 요소에 적절한 ARIA 레이블 제공
  * 색상만으로 정보를 전달하지 않고, 아이콘이나 텍스트를 함께 사용
  * 반응형 브레이크포인트는 모바일(<768px), 태블릿(768px-1024px), 데스크톱(>1024px)으로 설정
  * 터치 친화적인 인터랙티브 요소 크기 보장(최소 44x44px)

### 4. 주요 사용자 흐름의 E2E 검증 범위는 어디까지인가?
- 주요 사용자 흐름은 다음과 같은 순서로 검증해야 함:
  1. 로그인 → 대시보드 페이지 접근
  2. 기본 지표(총투자금, 총수익, 총수익률) 정상 표시 여부 확인
  3. 기간 선택 드롭다운을 통한 월별/연별 필터 적용 및 지표 변경 검증
  4. 투자자 필터, 증권사 필터 적용 시 지표 변화 확인
  5. 필터 조건에 해당하는 데이터가 없을 때의 빈 상태 처리 검증
  6. 반응형 화면 크기 변경 시 레이아웃 정상 적응 여부 확인
  7. 키보드 네비게이션을 통한 모든 인터랙티브 요소 접근 가능 여부 확인
- 검증 범위는 **데이터 표시 정확도, 필터 동작, 반응형 레이아웃, 접근성 기본 사항**까지이며, 실제 차트 라이브러리의 세부 애니메이션이나 인터랙션은 제외함

## 불확실한 점
| # | 불확실한 점 | 영향도 | 비고 |
|---|-------------|--------|------|
| 1 | 총투자금의 정확한 정의(청약금액 vs 배정금액 vs 증거금 등 중 어떤 기준을 사용할지) | 높음 | profit-calculation에서 공식 확인되지 않아 사용자 선택 옵션 제공 필요 |
| 2 | 대시보드에 표시할 차트 유형(라인, 바, 파이 등)과 구체적 시각화 방식 | 중 | 차트 라이브러리 선정 및 디자인 시스템 반영 후 결정 필요 |
| 3 | 지표 카드에 표시할 세부 정보 범위(전일 대비 변화율, 누적 값 등) | 낮음 | 사용자 시나리오 조사 및 디자인 시스템 가이드라인 반영 필요 |
| 4 | 필터 패널의 배치 위치(사이드바 vs 드롭다운 vs 별도 페이지)와 상호작용 방식 | 낮음 | 화면 크기별 반응형 동작 및 정보 구조 설계 후 결정 필요 |

## 결론
웹 투자 내역 대시보드는 매도 일시를 기간 필터의 기본 기준으로 하여 총투자금, 총수익, 총수익률 지표를 투자자별·증권사별·월별·연별로 표시해야 한다. 필터 조합은 AND 조건으로 작동하며 빈 결과의 경우 적절한 안내 메시지와 함께 수정이 가능한 인터랙티브 요소를 제공해야 한다. 접근성은 WCAG 2.1 AA 수준을, 반응형은 모바일 우선 접근법을 따라야 하며, 주요 사용자 흐름의 E2E 검증은 로그인부터 지표 보기, 필터 적용, 빈 상태 처리까지의 데이터 표시 정확도와 기본적인 인터랙션 동작을 포함해야 한다.
