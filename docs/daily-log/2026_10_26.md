## 리팩토링 후속 — 투자자·계좌·회원가입 응답 schema 경계

- 투자자와 증권계좌의 등록 응답을 entity response schema로 검증하고 mutation transport를 entity api-client로 이동했다. 계좌 수정/기본 지정 응답도 schema 검증을 적용했다.
- 원본 계좌번호 공개 응답은 `id/accountNumber/exposedAt` DTO를 별도로 검증한다. 민감한 번호 문자열은 `gcTime: 0` mutation에서만 반환되도록 기존 캐시 보호를 유지했다.
- 회원가입 응답은 backend `SignupResponse` 전체를 검증하며 UI fixture를 DTO 필드에 맞췄다. 테스트는 추가했지만 요청에 따라 실행은 종합 검증까지 보류한다: `NOT_RUN`.
- 공지 서비스의 직접 Spring 예외를 공통 업무 예외로 바꾸면 오류 JSON이 변할 수 있어 구현을 보류했다. 기존 400/404 status와 detail 메시지를 controller 테스트로 먼저 고정했다. backend 종합 검증은 여전히 `NOT_RUN`이다.
- 전체 mutation transport를 재검색해 notification subscribe/unsubscribe 응답 message와 broker confirm의 저장 매도 목록을 검증하도록 했다. broker confirm은 Sale schema가 필요한 복수 entity 흐름이라 `features/broker-sync`에 배치하고 공개 동작은 `Promise<void>`로 유지했다.


## styled-components 전환 및 시각 시스템 정리

- 사용자 요청: 제품 UI의 CSS Modules를 styled-components로 교체하고, 공통 UI를 추출하며, 시각 계층과 디자인 완성도를 높인다.
- `styled-components` 설치. 앱 토큰/reset을 `GlobalStyles.ts`로 옮기고, 공통 `Button`, `SurfaceCard`, `SectionHeading`, `Eyebrow`, `StatusPill`을 마련했다. EmptyState/ErrorMessage/Spinner/청약 상태 배지와 달력·IPO 상세의 동적 스타일을 styled components로 전환했다.
- 66개 CSS Module 파일을 제거하고 각 소유 FSD slice의 `*.styles.ts` + `StyleScope`로 옮겼다. 앱 스타일 registry나 화면별 공용 폴더는 두지 않았다. 디자인 토큰, header, main canvas, dashboard 지표, landing hero도 정리했다.
- 구현 직후 상태는 `NOT_RUN`; UI 전체 테스트·lint·typecheck·format·build는 사용자의 요청대로 최종 묶음에서 실행한다.

- 사용자 피드백에 따라 스타일 registry와 `shared/styles` 임시 구조를 제거하고 모든 스타일 파일을 원래 FSD 소유 slice로 배치했다. 참조 없는 `*.styles.ts`, 빈 디렉터리, 앱 소유 CSS/SCSS 파일이 없는 것을 확인했다. UI 전체 검증은 계획대로 최종 묶음까지 `NOT_RUN`이다.

- 최종 검증: UI 99개 테스트 파일/745개 통과, lint·typecheck·format:check·build PASS. backend 1,101개 테스트 통과, checkstyleMain/checkstyleTest/spotlessCheck/build PASS. `git diff --check` PASS. 62개 co-located 스타일은 모두 참조됨; 빈 디렉터리·앱 소유 CSS 파일은 없음. 브라우저 viewport 수동 점검과 hosted workflow/E2E는 NOT_RUN.
