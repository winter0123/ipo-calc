## 이슈 및 트러블슈팅

| 항목 | 내용 | 대응 |
|---|---|---|
| direnv 차단 | KIS 키를 채운 뒤 `.envrc`가 차단돼 호출 불가 | 사용자가 `direnv allow` 실행. 차단을 우회하지 않음 |
| 워커 교체 | OpenCode 워커를 띄웠다가 사용자가 Claude 터미널로 교체 지시, 이어서 워커 툴 사용 불가로 직접 구현 지시 | 교체 워커는 SF-4b를 끝냈고 Master가 슬롯 4에서 다시 검증. 이후 SF는 Master가 직접 구현 |
| 낡은 대기 | 새 `check --wait`가 `waiter_exists`로 거절 | 앞서 건 대기가 같은 Run의 메시지를 받으므로 재시도 불필요 |
| 키 수명 | 사용자가 "하루짜리 키"를 질문. 검색 결과가 24시간과 90일로 엇갈림 | 90일은 제휴사 문서로 판단. 24시간 토큰은 자동 갱신, 서비스 1년 사용기간은 공식 안내로 확인 |
| 다중 사용자 | 외부 사용자는 자동 연결 불가, 각자 키 입력 | D-B-013, 사용자 결정 대기 |
| 조회 기간 근거 오류 | SF-5 주석에 "KIS 조회 최대 89일"이라 적었으나 89일은 ustockplus 한도였다. KIS 문서에서 TTTC8715R 기간 한도를 찾지 못함 | D-B-016으로 정정(89일은 실호출 성공만 확인). 연속조회 미구현 한계는 D-B-017 |
| 토큰 만료 상태 결함 | 접근토큰(1일) 만료를 `EXPIRED`로 표시했으나 서버가 자동 재발급하므로 사용자가 할 일이 없다 | 상태를 서비스 사용기간(발급일+1년) 기준으로 교체(D-B-018) |
| 키 검증 스크립트 낡음 | 스캔 스크립트의 임시 vite 설정이 `@/` alias 없이 만들어져 E2E 12개가 모두 빈 화면에서 실패 | 실제 vite 설정을 병합하도록 수정 후 12/12 PASS |
| 토큰 캐시 미저장 | 앱 경유 실호출에서 두 번째 미리보기가 KIS 분당 제한(403 EGW00133). `preview`의 읽기 전용 트랜잭션 안에서는 토큰 캐시 저장이 반영되지 않았다 | #274로 트랜잭션 제거와 가드 테스트. 수정 뒤 토큰 발급 1회 |
| KIS HTTP 500 | 확정 직후 세 번째 미리보기에서 KIS가 500을 돌려줘 앱이 502로 변환 | 원인 미확인(추가 실호출 회피), D-B-024 |
| 연속조회 미검증 | 실계좌 응답이 2행뿐이라 다중 페이지로는 확인 못 함 | MockRestServiceServer 테스트로만 검증, 헤더 값 N은 공식 샘플 관례(D-B-017) |
