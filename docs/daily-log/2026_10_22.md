## Docker 운영 배포 구성 정리

- 운영 서버는 Ubuntu 홈 노트북에서 Docker 없이 systemd 백엔드, 호스트 PostgreSQL, Caddy 정적 프런트엔드로 운영 중임을 개인 배포 가이드와 대조했다.
- 저장소에는 운영용 Compose, 터널 오버레이, 앱 Dockerfile, Jenkins 컨테이너 설정, 예전 Docker 홈 서버 설치/업데이트 및 DB 백업/복원 스크립트가 남아 있어 제거했다.
- 루트 `docker-compose.yml`의 PostgreSQL 개발 DB만 유지하고, 구형 Docker 홈 서버 안내서는 현재 배포 가이드와 충돌해 제거했다.
- 로컬 Docker에서는 ipo-calc 운영 앱 3개와 Jenkins 컨테이너 및 전용 앱 이미지를 제거했다. 사용자의 지시에 따라 운영 PostgreSQL·Caddy 볼륨도 삭제했다. 개발 PostgreSQL과 Jenkins 볼륨 및 다른 저장소 컨테이너는 유지했다.
- 호스트 PostgreSQL 백업·복원은 새 운영 방식에 맞는 절차가 아직 없어 후속 작업으로 남겼다.
- 검증: `git diff --check` 통과, `docker compose config --services`에서 `postgres`만 확인. 자동 테스트는 실행하지 않음.

## 회원가입 시 본인 투자자 자동 생성

- 회원가입 화면에 투자자 등록의 표시 이름과 본인(SELF) 관계를 표시한다. 가입 서비스는 계정 생성 트랜잭션 안에서 ACTIVE 본인 투자자를 함께 저장하며, 서버는 다른 관계를 거부한다.
- 승인된 가입은 대시보드로 이동하고, 승인 대기 가입은 기존 승인 안내를 유지한다. 추가 투자자 등록 화면은 가족 등 추가 등록 용도로 남긴다.
- 다른 AI가 남긴 미완성 변경 중 승인 가입 테스트 컴파일 오류와 프런트 테스트의 JSON 키 순서 의존성을 수정했다. 투자자 API 테스트의 가입 준비 단계는 자동 생성 투자자를 제거해 각 API 시나리오를 독립적으로 검증한다.
- `web-account-setup` spec/architecture의 가입 흐름을 구현과 일치시켰다.
- 검증: 전체 백엔드 테스트 1,096건 및 Checkstyle PASS, 최종 수정 후 관련 백엔드 테스트 3개 클래스 PASS, UI 테스트 700건 및 lint/typecheck/format:check/build PASS, E2E 스크립트 `node --check`와 `git diff --check` PASS. 기본 백엔드 `build`는 저장소 내 기존 Spotless 위반(변경 범위 밖 다수 파일)으로 실패했으며 범위 밖 파일은 일괄 포맷하지 않았다. `build -x spotlessJavaCheck`는 PASS. 실제 브라우저 E2E는 실행하지 않았다.

- 설정 메뉴에 마이페이지를 추가해 가입 계정·본인 투자자 정보를 조회한다.
