# 워커 spec 템플릿

무료 모델 워커에게 주는 task spec의 형식이다. **자기완결적이어야 한다** — 워커는 이 세션의 대화 맥락을 모르고, 되물을 수단도 사실상 없다.

무료 모델이 실제로 저지른 실수(2026-09-28 관측): ① 지시하지 않은 파일까지 건드림, ② 이미 구현된 API를 "미구현"으로 단정, ③ 자기가 만든 테스트 회귀를 "기존 문제"라고 보고, ④ 검증 명령을 지어냄. 아래 항목은 전부 이 실수들을 막으려고 있는 것이니 빼지 않는다.

## 형식

```
[역할] <backend|frontend|planning> 워커. 작업공간: <절대경로> (브랜치 <branch>)

[목적] <이 SF가 무엇을 위한 것인지 한 문장>

[먼저 읽을 것]
- docs/breakdown/<slug>.md 의 <SF-N> 섹션  ← AC 목록의 진실 소스
- docs/guide-<role>.md  ← 기술스택·코드 스타일·검증 명령
- <참고할 기존 구현 파일 경로 2~3개>  ← 같은 패턴을 재사용하라는 뜻

[범위 — 수정해도 되는 파일]
- <경로1>
- <경로2>
(여기 없는 파일은 건드리지 않는다. 필요하면 진행을 멈추고 보고한다.)

[범위 밖 — 건드리지 말 것]
- <이미 병합된 기능, 공용 설정, 다른 Epic 패키지 등>
- (backend) `docs/guide-backend.md` 5절 "워커가 자주 밟는 지뢰"를 그대로 복사해 붙인다 — spotlessApply 금지, 슬롯 DB 규칙, Javadoc 마침표 등
- (backend) **코디네이터가 [검증] 명령에 지정한 슬롯 번호(DB_NAME)만 쓴다.** 슬롯이 적히지 않았다면 진행을 멈추고 "슬롯 몇 번을 쓰면 되나요?"를 되묻는다. 임의로 `DB_NAME`을 정하거나, 슬롯 없이 기본 DB(`ipo_calc`)로 테스트하지 않는다.

[해야 할 일]
1. <구체적 단계>
2. <구체적 단계>

[구현해야 할 AC]
- AC-0NN: <조건 → 기대 결과>
- AC-0NN: <조건 → 기대 결과>

[이미 구현된 것 — 다시 만들지 말 것]
- <엔드포인트/컴포넌트>: <파일경로>에 이미 있음

[검증 — 반드시 이 명령을 그대로 실행하고 출력을 보고에 붙인다]
<guide-<role>.md에서 복사한 실제 명령>
예) scripts/db-slot.sh reset 1   # (backend) 코디네이터가 배정한 슬롯 번호로 먼저 reset — 배정된 번호만 쓴다
예) DB_NAME=ipo_slot_1 DB_PASSWORD=ipo_local_password ./gradlew test --rerun
예) DB_NAME=ipo_slot_1 DB_PASSWORD=ipo_local_password ./gradlew checkstyleMain checkstyleTest --rerun-tasks -q   (task를 여러 개 쓸 때 `--rerun`은 마지막 task에만 적용되므로 `--rerun-tasks`)
예) pnpm run test && pnpm run lint && pnpm run typecheck && pnpm run build

[완료 조건]
- 위 검증 명령이 전부 통과
- `git diff --stat` 결과가 [범위]에 적힌 파일만 포함
- 커밋하지 않는다. 변경사항을 워킹트리에 둔 채로 worker_done을 보고한다.

[보고 형식]
- 수정한 파일 목록 (git diff --stat 출력 그대로)
- 검증 명령 출력의 마지막 20줄
- 실패한 테스트가 있으면: 실패 원인과, 그게 이번 변경 때문인지 기존 문제인지 판단한 근거
  (기존 문제라고 주장하려면 `git stash`로 변경을 빼고 재실행해 확인한 결과를 붙인다)
```

## 코디네이터가 spec을 쓸 때 지키는 것

- **AC를 복사해 넣는다**: "breakdown 문서 보고 알아서 해라"로 넘기면 워커가 문서를 잘못 읽는다.
- **검증 명령은 실제 파일에서 복사한다**: 기억으로 쓰지 말고 `docs/guide-<role>.md`나 `build.gradle.kts`/`package.json`을 확인해서 쓴다. 없는 task(예: 이 저장소에 아직 없는 `checkstyleMain`)를 적으면 워커가 거기서 막힌다.
- **커밋은 시키지 않는다**: 코디네이터가 검증한 뒤 커밋·PR을 만든다. 워커가 커밋까지 하면 잘못된 변경을 되돌리기 번거로워진다.
- **한 spec = 한 SF**: 여러 SF를 한 워커에 묶으면 diff가 커져 검증 비용이 올라가고, 실패 시 롤백 단위가 뭉개진다.

## 이어받는 워커와 이어 쓰기 세션

**재개 spec**: 이전 워커가 멈춰서 같은 SF를 다른 워커에게 넘길 때는, 작업공간에 남은 부분 진행분을 버리지 않는다. spec 끝에 다음 문장을 덧붙인다.

```
[재개] 작업공간에는 이전 워커가 만든 진행분이 이미 있다. 먼저 `git status --short`와 `git diff`로 현재 상태를 확인하고,
처음부터 다시 만들지 말고 이어서 완성한다. 이미 있는 파일이 이 spec의 [범위]와 다르면 임의로 지우지 말고 보고한다.
```

**이어 쓰기 세션(예외)**: 같은 패키지에서 앞 SF의 코드를 뒤 SF가 이어 쓰는 경우(AGENTS.md 7.1.1절의 "순차가 필수인 경우")에 한해, 앞 SF를 끝낸 워커의 터미널을 닫지 않고 뒤 SF spec을 같은 터미널에 이어서 줄 수 있다. 코드를 이미 읽은 상태라 콜드스타트 비용이 사라진다. 조건은 다음과 같다.

- 뒤 SF도 위 형식의 자기완결적 spec으로 준다("아까 하던 것 이어서"라고 말로 넘기지 않는다).
- 앞 SF는 **Master 검증과 병합이 끝난 뒤**에 이어 준다. 병합 전 코드 위에 다음 SF를 쌓지 않는다.
- 터미널 화면의 컨텍스트 사용률이 50%를 넘었거나, 워커가 한 번이라도 실패·정체했거나, 모델이 바뀌면 그 터미널을 버리고 새 워커로 시작한다.
- worktree와 브랜치는 SF마다 새로 만드는 원칙(AGENTS.md 7.2절)을 그대로 지킨다. 재사용하는 것은 터미널(워커 세션)뿐이다.
