> Epic 번호: 22, slug: `announcements`
> 작성일: 2026-10-23

## 1. 사용자 목표

관리자가 공지사항을 등록·수정·삭제·조회하고, 모든 로그인 사용자가 홈(대시보드) 첫 진입 시 활성 공지사항을 팝업으로 확인하며, 상세 화면으로 이동할 수 있다. 사용자는 팝업에서 **닫기**(다음 로그인 시 다시 표시) 또는 **다시 보지 않기**(이메일 계정 기준 서버 DB 저장으로 영구 숨김)를 선택할 수 있다. 공지사항은 공모주(IPO)와 독립된 기능/데이터다.

## 3. 기능 범위 (In Scope)

| 기능 | 설명 |
|------|------|
| 공지사항 CRUD (관리자) | 제목, 내용(마크다운/HTML), 시작일, 종료일(KST 날짜, 양쪽 포함), 상태(ACTIVE/CANCELLED) |
| 공지사항 목록·상세 조회 (로그인 사용자) | 활성·기간 내 공지만 노출, 페이지네이션, 정렬(시작일 순) |
| 홈 첫 진입 팝업 노출 | 로그인 후 대시보드 최초 진입 시 활성 공지 전부 순차 표시 |
| 팝업 액션: 닫기 | 세션/로그인 기준 다음 진입 시 재표시 |
| 팝업 액션: 다시 보지 않기 | 이메일 계정(계정 ID) 기준 서버 DB 저장으로 영구 숨김, 기기 간 동기화 |
| 상세 페이지 | 전체 내용 렌더링(마크다운/HTML), 메타 정보 표시 |
| 관리자 메뉴 통합 | MainLayout의 ADMIN_ITEMS에 "공지사항 관리" 추가 (`/admin/announcements`) |
| 권한 제어 | 관리자 API: ADMIN만, 조회 API: 로그인 사용자 모두, 비로그인: 401 |
| 공모주(IPO)와 독립 | 공지사항은 IPO 엔티티·API와 무관하게 별도 도메인으로 구현 |

## 4. 비범위 (Out of Scope)

| 기능 | 사유 |
|------|------|
| 공지사항 카테고리/태그 | MVP 범위 아님, 향후 확장 시 고려 |
| 공지사항 첨부파일 | 복잡도 증가, 필요시 별도 Epic |
| 푸시 알림/이메일 연동 | 기존 notification 도메인과 별도, 현재는 인앱 팝업만 |
| 다국어 지원 | 한국어만 |

| 비로그인 사용자 대상 공개 공지 | 요구사항에 없음, 로그인 사용자만 대상 |
| 공지사항 예약 발행(자동 활성화) | 시작일 기반 자동 활성화는 구현, 별도 스케줄러 불필요(조회 시 기간 필터로 처리) |

## 5. Acceptance Criteria (AC)

### 5.1 백엔드 API

| AC ID | 조건 | 기대 결과 |
|-------|------|-----------|
| AC-BE-01 | `POST /api/admin/announcements` (ADMIN) | 유효한 요청 시 201 Created + 생성된 공지사항 응답, 필수 필드 누락 시 400 |
| AC-BE-02 | `GET /api/admin/announcements` (ADMIN) | 전체 목록(페이지네이션, 상태 필터) 200 OK |
| AC-BE-03 | `GET /api/admin/announcements/{id}` (ADMIN) | 단건 조회 200 OK, 없으면 404 |
| AC-BE-04 | `PATCH /api/admin/announcements/{id}` (ADMIN) | 수정 성공 200 OK, 없으면 404, 권한 없으면 403 |
| AC-BE-05 | `DELETE /api/admin/announcements/{id}` (ADMIN) | 논리 삭제 성공 204 No Content (`status=CANCELLED`, `deleted_at=now()`), 없으면 404 |
| AC-BE-06 | `GET /api/announcements` (로그인) | 활성·기간 내 공지 목록 200 OK (페이지네이션, 정렬: start_at ASC) |
| AC-BE-07 | `GET /api/announcements/{id}` (로그인) | 활성·기간 내 단건 조회 200 OK, 비활성/기간 외/없으면 404 |
| AC-BE-08 | `GET /api/announcements/popup` (로그인) | **홈 첫 진입용**: 사용자에게 노출할 활성 공지 전부 반환 (없으면 204 No Content), "다시 보지 않기"한 공지 제외 (계정 ID 기준 DB 조회) |
| AC-BE-09 | `POST /api/announcements/{id}/dismiss` (로그인) | "다시 보지 않기" 저장 성공 200 OK, 이미 저장됐으면 200 OK(멱등) — 계정 ID 기준 DB 저장 |
| AC-BE-10 | 권한 검증 | ADMIN API에 일반 사용자 요청 → 403, 비로그인 요청 → 401 |
| AC-BE-11 | 입력 검증 | 제목 필수(1~200자), 내용 필수(1~10000자), 시작일 ≤ 종료일(KST 날짜), 상태 ACTIVE/CANCELLE |
| AC-BE-12 | 논리 삭제 | DELETE 시 `status=CANCELLED`, `deleted_at=now()`, 조회 쿼리에서 `status=ACTIVE AND deleted_at IS NULL` 필터 |
| AC-BE-13 | IPO 독립성 | 공지사항 API는 `/api/ipos/**` 경로와 무관, 별도 `/api/announcements/**` 경로 사용 |

### 5.2 프론트엔드

| AC ID | 조건 | 기대 결과 |
|-------|------|-----------|
| AC-FE-01 | 관리자 메뉴 | ADMIN 권한 사용자 헤더 메뉴에 "공지사항 관리" 표시, 클릭 시 `/admin/announcements` 이동 |
| AC-FE-02 | 관리자 목록 페이지 | `/admin/announcements`에서 테이블로 전체 공지 표시(상태 배지, 기간), 등록/수정/삭제 버튼 동작 |
| AC-FE-03 | 관리자 등록/수정 폼 | 제목·내용(텍스트에리어)·시작일·종료일(KST 날짜)·상태 입력, 유효성 검증(필수, 날짜 순서), 저장 시 API 호출 |
| AC-FE-04 | 관리자 삭제 확인 | 삭제 버튼 클릭 시 `ConfirmDialog`로 재확인, 확인 시 API 호출 후 목록 갱신 |
| AC-FE-05 | 사용자 목록 페이지 | `/announcements`에서 활성 공지 카드/리스트 표시, 클릭 시 상세 이동 |
| AC-FE-06 | 사용자 상세 페이지 | `/announcements/{id}`에서 제목·내용·기간·상태 표시, "목록으로" 버튼 |
| AC-FE-07 | 홈 첫 진입 팝업 | 로그인 후 `/dashboard` 최초 진입 시(세션 기준) `GET /api/announcements/popup` 호출, 데이터 있으면 모달 순차 표시 |
| AC-FE-08 | 팝업 UI | 제목, 내용 요약(첫 200자), "자세히 보기" 링크, "닫기", "다시 보지 않기" 버튼, 접근성(role="dialog", 포커스 트랩, Escape 닫기) |
| AC-FE-09 | 팝업 "닫기" 액션 | 모달 닫기, 서버 호출 없음, 다음 재접속/새 방문 시 같은 공지 다시 팝업 표시 |
| AC-FE-10 | 팝업 "다시 보지 않기" 액션 | `POST /api/announcements/{id}/dismiss` 호출 성공 시 모달 닫기, 이후 팝업 조회 API에서 해당 공지 제외 (계정 ID 기준) |
| AC-FE-11 | 팝업 "자세히 보기" | `/announcements/{id}`로 네비게이션, 모달 닫기 |
| AC-FE-12 | 반응형·접근성 | 모바일(≤640px)에서 팝업 전체 화면 모달, 키보드 네비게이션, 스크린리더 라벨, 색 대비 WCAG 2.1 AA |
| AC-FE-13 | 에러 상태 | API 실패 시 인라인 에러 메시지(`role="alert"`), 네트워크 에러 시 토스트성 안내 |
| AC-FE-14 | 빈 상태 | 활성 공지 없을 때 목록 페이지 "등록된 공지사항이 없습니다" 표시 |

## 6. 엣지 케이스

| 케이스 | 처리 방침 |
|--------|-----------|
| 시작일 > 종료일 요청 | 400 Bad Request (AC-BE-11) |
| 과거 종료일 공지 등록 | 허용(즉시 비활성화됨), 관리자 목록엔 보임 |
| 동일 시작일 다중 공지 | ID 오름차순으로 타이브레이크 |
| "다시 보지 않기" 후 관리자가 공지 수정 | dismissal 유지(공지 ID 기준), 수정된 내용으로 다시 보이게 하려면 관리자가 새 공지 생성 |
| 사용자가 로그아웃 후 다른 계정 로그인 | dismissal은 계정별이므로 새 계정은 다시 팝업 표시 |
| 세션 만료 후 재로그인 | "닫기"한 공지는 재표시, "다시 보지 않기"한 공지는 숨김 유지 (DB 저장) |
| 브라우저 프라이빗 모드(localStorage 불가) | "닫기" 상태는 이번 방문에서만 유지되고 재접속/새 방문 시 초기화, "다시 보지 않기"는 DB 저장으로 기기 간 영구 숨김 |
| 다중 탭에서 동시 팝업 | 각 탭 독립 동작, "다시 보지 않기" 클릭 시 타 탭은 다음 팝업 조회 시 제외됨(폴링 불필요) |

## 7. 확정 사항 요약 (모든 게이트 해제) — 연구 문서 9절 참조

> **모든 게이트(GT-01~GT-07)는 사용자 요청으로 확정되어 별도 게이트 불필요.** 구현 시 확정된 값만 적용하며 임의 값 가정 금지.

| 게이트 ID | 내용 | 확정 값 | 비고 |
|-----------|------|---------|------|
| GT-01 | 시작/종료 시각 포함 단위 | KST 날짜 기준, 시작일~종료일 양쪽 포함 (`LocalDate`, 종료일 23:59:59까지) | 게이트 불필요 |
| GT-02 | "다시 보지 않기" 저장소 | 이메일 계정(계정 ID) 기준 서버 DB 저장 | 게이트 불필요 |
| GT-03 | 비로그인 사용자에게 팝업 표시 | 로그인 사용자만 (사용자 요청) | 게이트 불필요 |
| GT-04 | 다중 활성 공지 노출 우선순위 | 전부 순차 표시, priority 컬럼/입력 필드 불필요 | 게이트 불필요 |
| GT-05 | "홈 첫 진입" 정의 | 로그인 후 대시보드 최초 진입 (사용자 요청) | 게이트 불필요 |
| GT-06 | "닫기" 후 재접속 시 재표시 | 재접속 시 재표시 (이번 방문에서만 닫힘) | 게이트 불필요 |
| GT-07 | 관리자 공지 관리 메뉴 경로 | 기존 admin route 패턴 `/admin/announcements` | 게이트 불필요 |

> **확정 사항 (게이트 불필요)**: 관리자 CRUD, 로그인 사용자 읽기, 기간 경계(KST 날짜, 시작일~종료일 양쪽 포함), 팝업 노출 구조(전부 순차), 상세 이동, "닫기"(이번 방문에서만 닫고 다음 재접속/새 방문에 재표시), "다시 보지 않기"(계정 기준 서버 DB 영구 숨김), 삭제(관리자 전용, 기존 `RecordStatus` + `deleted_at` 패턴 준용: `status=CANCELLED`, `deleted_at=now()` 논리 삭제, 조회 쿼리는 `status=ACTIVE AND deleted_at IS NULL` 필터), IPO 독립성.
