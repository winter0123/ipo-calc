# 상장일 시초가로 매도단가 자동 채움 명세 (listing-open-price)

> **Epic**: E21 (상장일 시초가로 매도단가 자동 채움, listing-open-price)
> **범위**: SF-1~SF-3 전체. 매도 등록 폼의 첫 매도단가 기본값을 "공모가 → 상장일 시초가"로 전환한다.
> **기준 문서**: `docs/research/listing-open-price.md`(2026-10-16), `docs/breakdown/listing-open-price.md`, `docs/spec/ipo-schedule-sync.md`, `docs/architecture/ipo-schedule-sync.md`
> **언어**: 한국어 (표준 IT 용어 한정)
> **상태**: 착수 준비 완료 — 실호출 게이트(§7(a)) 통과(2026-10-16 Master 실측). 남은 미결정은 U-6(안내 문구)뿐

## 문서 개요

이 문서는 Epic 21의 구현 명세다. 공공데이터포털 "금융위원회_주식시세정보"(`getStockPriceInfo`)에서 공모주의 **상장일 시초가(시가)**를 수집해 `ipos`에 저장하고, 매도 등록 폼의 매도단가 기본값으로 채운다. 시초가를 모르는 경우(미수집·종목코드 없음 등)는 지금처럼 공모가가 들어가며, 사용자는 값을 고칠 수 있다.

**이미 확정된 사용자 결정(2026-10-16, 재논의 대상 아님)**

1. 매도 등록 화면에서 처음 들어가는 매도단가는 "그 공모주의 상장일 시초가"다. 시초가를 모르면 지금처럼 공모가를 넣는다. 사용자는 값을 고칠 수 있다.
2. 시세 출처는 공공데이터포털 "금융위원회_주식시세정보"(GetStockSecuritiesInfoService / getStockPriceInfo), 키는 기존 `DATA_GO_KR_SERVICE_KEY`를 그대로 쓴다.
3. 증권사 API 연동(/broker-sync)과 증권사 앱 캡처 OCR 가져오기(#452, `CaptureImport`)는 **그대로 유지**한다. 캡처나 증권사 값으로 채우면 그 값이 시초가 기본값보다 우선한다.
4. "상장일 시가로 전량 매도 기록" 원클릭 버튼은 이번 범위에 넣지 않는다.

## 1. 개요

### 1.1 목표

매도 등록 시 매도단가 칸에 처음 채워지는 값을 "공모가(배정단가 우선 규칙 유지)"에서 **"상장일 시초가 → 없으면 기존 공모가 규칙"**으로 바꾼다. 시초가는 백엔드 일일 배치가 외부 시세 API에서 수집해 `ipos`에 저장하고, 기존 `GET /ipos`·`GET /ipos/{id}` 응답에 노출한다.

### 1.2 비범위

- 증권사 API 연동(/broker-sync), 캡처 OCR 가져오기(#452)의 변경 — 없다(값의 우선순위만 규칙으로 명시).
- "상장일 시가로 전량 매도 기록" 원클릭 버튼 — 없다(미결정 사항 U-5).
- 매도 수정 화면(`SaleEditDialog`)의 기본값 변경 — 없다(이미 저장된 기록을 보여주는 화면).
- 시세 차트·시가총액 등 시세 기반 추가 기능 — 없다.
- 새 인증키(기존 `DATA_GO_KR_SERVICE_KEY` 재사용).

### 1.3 SF 간 의존성

```
SF-1 (백엔드: 마이그레이션 + 시세 클라이언트 + 일일 배치)
  → SF-2 (IPO 응답에 시초가 노출 + 프론트 Zod 스키마)
       → SF-3 (매도 폼 기본값 + 안내 문구)
```

## 2. 용어

| 용어 | 정의 |
|------|------|
| 시초가 | 상장 첫 거래일의 정규시장 시가. API 응답 필드 `mkp`(2026-10-16 실측 확정, 값은 JSON 문자열 — research §3) |
| 상장일 | `ipos.listing_date`. 시초가의 기준일(`basDt`) |
| 단축코드 | KRX 6자리 종목코드. `ipos.stock_code`, API 검색 파라미터 후보 `likeSrtnCd` |
| 시세 배치 | Epic 21이 새로 만드는 일일 배치(`IpoOpenPriceSyncScheduler`, 가칭) |
| 기본값 채움 | `useSaleForm`의 청약 선택 시점 1회성 `setValue`(isDirty 칸 제외) |
| 캡처 값 | 증권사 앱 캡처 OCR로 파싱돼 폼에 적용되는 값(`useCaptureImport`) |

## 3. 사용자 시나리오

### S-1. 시초가가 수집된 공모주를 매도 등록 (정상 경로)

1. 사용자가 매도 등록 화면에서 청약을 선택한다.
2. 청약·공모주 정보가 도착하면 매도단가 칸에 **상장일 시초가**가 들어간다.
3. 매도단가 안내 문구에 시초가임이 표시된다(예: "상장일 시초가 21,500원이 먼저 들어갑니다." — 문구 확정은 SF-3).
4. 사용자가 실제 체결가로 고쳐 제출한다(또는 그대로 두고 제출).

### S-2. 시초가를 아직 모르는 공모주 (미수집·상장 전·종목코드 없음)

1. 청약을 선택하면 매도단가 칸에 지금처럼 **공모가**(배정단가 우선 규칙 `resolveIpoPrice` 그대로)가 들어간다.
2. 안내 문구도 지금처럼 공모가 안내를 보여준다.
3. 시초가가 나중에 수집돼도 이미 열어둔 폼은 변경하지 않는다(새로 선택하거나 새로고침한 시점에 반영).

### S-3. 시초가보다 실제 매도가가 다를 때

1. 사용자는 시초가 기본값을 보고 실제 체결가로 고친다.
2. 세금·실현손익 연계 계산은 기존과 동일하게 고친 값 기준으로 재계산된다(`syncLinked` 유지).

### S-4. 캡처로 가져온 경우

1. 사용자가 증권사 앱 화면 캡처 여러 장을 업로드한다(#452).
2. OCR 파싱된 체결가(매도단가)가 시초가 기본값을 **덮어쓴다**(기존 캡처 우선 규칙 유지).
3. 캡처 값에는 기존대로 CapturedBadge가 표시된다.

### S-5. 이미 고쳐 둔 칸

1. 사용자가 매도단가를 고친 뒤 같은 청약을 유지하는 동안 값은 유지된다(재선택·초기화 없으면 다시 채움되지 않음).
2. 청약을 바꾸면 전체 필드가 초기화되고 새 청약의 시초가(또는 공모가) 기본값이 다시 들어간다(기존 `clearSaleFields` 흐름 유지).

### S-6. 매도 수정(SaleEditDialog)

1. 기존 매도 기록을 수정할 때는 **저장된 값**이 그대로 보인다. 시초가를 새로 참조하지 않는다(변경 없음).

### S-7. 시세 API가 죽어 있어도

1. 배치 실패(403·네트워크·키 미설정) 시 서버와 다른 기능은 정상이고, 시초가만 NULL로 남는다.
2. 매도 등록은 S-2 경로(공모가 기본값)로 계속 동작한다.

## 9. Acceptance Criteria (AC-2101~2110)

**AC-2101**: 시세 배치가 상장일이 지난 공모주의 시초가를 수집해 저장한다
- Given: `DATA_GO_KR_SERVICE_KEY`가 유효하고(활용신청 승인 완료), ACTIVE 공모주 A가 `stock_code="123456"`, `listing_date=2026-10-15`, `listing_open_price=NULL`이며, 시세 API가 A의 상장일 시세(`mkp=21500`)를 반환한다
- When: 시세 배치가 실행된다
- Then: A의 `listing_open_price`가 21500으로 저장된다

**AC-2102**: 인증키 미설정·403(활용신청 미완료) 시 배치만 중단되고 서버는 정상이다
- Given: `DATA_GO_KR_SERVICE_KEY`가 비어 있거나, 시세 서비스 미승인으로 403(`SERVICE_KEY_IS_NOT_REGISTERED_ERROR`)이 돌아온다
- When: 앱이 기동하고 시세 배치가 실행 시도된다
- Then: 앱은 정상 기동하며(기동 실패 금지), 다른 API·화면은 정상 동작한다. 배치는 WARN/ERROR 로그를 남기고 종료한다(무한 재시도 없음, 다음 일일 주기 전까지 중단)

**AC-2103**: 종목코드가 없는 공모주는 조회 시도 없이 건너뛴다
- Given: ACTIVE 공모주 B가 `stock_code=NULL`, `listing_date=2026-10-10`, `listing_open_price=NULL`이다
- When: 시세 배치가 실행된다
- Then: B에 대한 외부 API 호출이 발생하지 않고, B의 `listing_open_price`는 NULL로 남는다

**AC-2104**: IPO 조회 응답에 시초가가 노출된다
- Given: 시초가 21500이 저장된 공모주 A가 있다
- When: `GET /ipos/{A.id}`(또는 `GET /ipos`)가 호출된다
- Then: 응답 JSON에 `"listingOpenPrice": 21500`이 포함된다. 시초가가 없는 공모주는 `null`이다. 프론트 `ipoSchema`로 파싱에 실패하지 않는다

**AC-2105**: 시초가가 있으면 매도 등록 폼의 매도단가에 시초가가 들어간다
- Given: 로그인한 투자자의 청약이 공모주 A(시초가 21500, 확정공모가 15000)에 연결되어 있고, 매도 등록 화면에서 이 청약을 선택한다
- When: 청약·공모주 정보가 도착한다
- Then: 매도단가 칸에 21500이 채워지고, 안내 문구에 시초가임이 표시된다

**AC-2106**: 시초가가 없으면 기존 공모가 규칙이 그대로 적용된다
- Given: 시초가 NULL인 공모주 C(확정공모가 15000, 배정단가 14000)의 청약을 선택한다
- When: 청약·공모주 정보가 도착한다
- Then: 매도단가 칸에 기존 규칙(공모가 우선, `resolveIpoPrice`)과 같은 값이 채워지고, 안내 문구도 기존 공모가 안내를 보여준다

**AC-2107**: 사용자가 이미 고친 매도단가는 시초가 기본값으로 덮어써지지 않는다
- Given: 매도 등록 폼에서 매도단가를 사용자가 30000으로 고쳐 둔 상태에서 같은 청약에 대해 값 채움 로직이 다시 실행된다(청약 유지 시 재실행 없음 — 청약 전환 후 복귀 등)
- When: 기본값 채움 조건이 다시 만족된다
- Then: 매도단가는 30000을 유지한다(isDirty 칸은 건드리지 않음, 기존 동작 유지)

**AC-2108**: 캡처로 가져온 체결가는 시초가 기본값보다 우선한다
- Given: 시초가 21500이 기본값으로 채워진 매도 폼에, 캡처 OCR 결과 체결가 25000이 적용 대상으로 들어온다
- When: 캡처 적용이 실행된다
- Then: 매도단가는 25000으로 바뀌고 CapturedBadge가 표시된다

**AC-2109**: API가 시가 0(또는 비정상 짧은 값)을 반환하면 유효값으로 쓰지 않는다
- Given: 시세 API가 공모주 D의 상장일 시세로 `mkp=0`(또는 빈 문자열)을 반환한다
- When: 배치가 응답을 처리한다
- Then: D의 `listing_open_price`는 NULL로 남는다(0 저장 금지)

**AC-2110**: 테스트 실행 시 시세 배치가 실행되지 않는다
- Given: `./gradlew test` 환경(`build.gradle.kts`의 `tasks.test`)
- When: 테스트가 실행된다
- Then: 시세 배치 빈이 비활성화되어 외부 시세 API 호출·스케줄 실행이 없다(기존 `app.holiday-sync.enabled=false` 패턴 동일)

> **SF-2~3 세부 AC**: breakdown §SF-2·§SF-3의 AC 초안 참조(AC-2120~, AC-2130~). 이 spec의 AC-2101~2110이 관찰 기준의 본체다.
