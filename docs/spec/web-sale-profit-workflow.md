## 1. 매도 등록 화면

### 화면 목적
사용자가 배정을 선택하고 매도수량·단가·금액·일시·수수료·세금·기타비용을 입력하여 매도를 등록한다. 배정 선택은 드롭다운으로 제공하며, 배정의 남은 수량을 참고 표시한다. 매도 등록은 별도 화면으로 운영된다(D-W15-006).

### 사용하는 API
- `GET /investment-history/{subscriptionId}` (D-W15-005, Epic 11) — 배정 참고 정보 조회
  - 응답에 `allocation.allocatedQuantity`, `sales[]`, `remainingQuantity` 참고 표시용
- `POST /sales` (D-W15-005) — 매도 등록
  - 요청: `{ allocationId, quantity, price?, amount?, saleDate, fee?, tax?, otherCost? }`
  - 응답 201: 매도 등록 성공
  - 응답 400: 유효성 오류 (누적매도수량>배정수량 등)
  - 응답 404: 배정을 찾을 수 없음
  - 응답 409: 충돌

### 폼 필드

| 필드명 | 타입 | 필수 | 프론트엔드 유효성 검사 규칙 |
|--------|------|------|-----------------------------|
| allocationId | select | 예 | 배정 드롭다운에서 선택 — 필수. `GET /investment-history/{subscriptionId}`로 남은 수량 참고 표시 |
| referenceQuantity | number | 아니오 | 선택된 배정의 `remainingQuantity`를 **참고 표시**만 (읽기 전용) |
| quantity | number | 예 | 0 초과 정수만 검증 (sale-management spec 기준). 서버가 누적매도수량>배정수량 검증을 수행하므로 프론트는 UX 보조만 제공 (D-W15-004) |
| price | number | 아니오 | 선택 사항 (API에서 `?`로 명시). 0 이상 정수만 검증 (sale-management spec 기준) |
| amount | number | 아니오 | 선택 사항 (API에서 `?`로 명시). 0 이상 정수만 검증 |
| saleDate | datetime-local | 예 | 매도 일시 선택 — 필수 |
| fee | number | 아니오 | 수수료 — 선택 사항 (API에서 `?`로 명시). 0 이상 정수만 검증 |
| tax | number | 아니오 | 세금 — 선택 사항 (API에서 `?`로 명시). 0 이상 정수만 검증 |
| otherCost | number | 아니오 | 기타비용 — 선택 사항 (API에서 `?`로 명시). 0 이상 정수만 검증 |

### 참고 표시 (D-W15-001, D-W15-005)
- 선택된 배정의 `remainingQuantity`(남은 수량)를 폼 상단에 참고 표시로 보여준다.
- 프론트는 남은 수량 대비 매도수량이 초과되지 않는지 **UX 보조**로 안내할 수 있으나, 최종 검증은 서버가 수행한다.
- 서버 400 응답(누적매도수량>배정수량) 시 해당 에러 메시지를 인라인 에러로 그대로 표시한다.

### 화면 상태

| 상태 | 설명 | UI 동작 |
|------|------|---------|
| 초기 (idle) | 폼이 초기화된 상태 | 모든 필드 빈 값, 드롭다운 로딩 중, 에러 메시지 숨김 |
| 로딩 (loading) | 배정 조회 또는 API 호출 중 | 제출 버튼 비활성화, 스피너 표시 |
| 성공 (success) | 201 응답 수신 | 성공 메시지 표시, 매도 목록(Epic 11 투자내역 화면)으로 이동 |
| 에러 (error) | 400/404/409 응답 또는 네트워크 오류 | 필드 아래 인라인 에러 메시지 표시 |

### 에러 처리 (D-W15-004: 락 충돌 UI 설계 금지)

| 에러 유형 | 필드 | 인라인 에러 메시지 |
|-----------|------|-------------------|
| 404 Not Found (배정 미존재) | allocationId | "배정을 찾을 수 없습니다." |
| 409 Conflict | 전체 폼 | 서버 응답 에러 메시지를 그대로 표시 (락 충돌 UI 없음, D-W15-004) |
| 400 Bad Request (누적매도수량>배정수량) | quantity | 서버 응답 메시지를 그대로 표시 (예: "누적 매도수량은 배정수량을 초과할 수 없습니다.") |
| 400 Bad Request | 해당 필드 | API 응답의 에러 메시지를 매핑하여 표시 |
| 네트워크 오류 | 전체 폼 | "네트워크 연결을 확인해 주세요." |
| quantity 0 이하 | quantity | "0 초과 정수를 입력해 주세요." |
| price 음수 (입력 시) | price | "0 이상의 정수를 입력해 주세요." |
| amount 0 미만 (입력 시) | amount | "0 이상의 정수를 입력해 주세요." |
| fee/tax/otherCost 0 미만 (입력 시) | 해당 필드 | "0 이상의 정수를 입력해 주세요." |

### 성공 후 이동 경로
- 매도 등록 성공(201) → Epic 11의 투자 내역 화면(`GET /investment-history`)으로 이동
- 등록된 매도가 목록에 즉시 표시되는지 확인
- 매도 순서는 saleDate 기준 정렬로 표시 (D-W15-003, 순번 필드 없음)

## 2. 비용 등록 화면

### 화면 목적
사용자가 청약을 선택하고 비용종류·금액·발생일시·메모를 입력하여 비용을 등록한다. 비용 등록은 별도 화면으로 운영된다(D-W15-006).

### 사용하는 API
- `POST /costs` (D-W15-005) — 비용 등록
  - 요청: `{ subscriptionId, costType, amount, incurredAt, memo? }`
  - 응답 201: 비용 등록 성공
  - 응답 400: 유효성 오류
  - 응답 404: 청약을 찾을 수 없음

### 폼 필드

| 필드명 | 타입 | 필수 | 프론트엔드 유효성 검사 규칙 |
|--------|------|------|-----------------------------|
| subscriptionId | select | 예 | 청약 드롭다운에서 선택 — 필수 |
| costType | select | 예 | 비용종류 드롭다운에서 선택 — 필수 |
| amount | number | 예 | 0 초과 정수만 검증 |
| incurredAt | datetime-local | 예 | 비용 발생일시 선택 — 필수 |
| memo | textarea | 아니오 | 메모 — 선택 사항, 입력 시 빈 문자열 허용 |

### 화면 상태

| 성공 (success) | 201 응답 수신 | 성공 메시지 표시, 비용 목록 화면으로 이동 |
| 에러 (error) | 400/404 응답 또는 네트워크 오류 | 필드 아래 인라인 에러 메시지 표시 |

## 3. 수익 확인 화면

### 화면 목적
사용자는 특정 매도건 또는 투자자별로 수익을 조회한다. 이 화면은 읽기 전용이며, 입력 폼이 없다. 수익 결과는 API 응답 필드를 그대로 표시한다(CalculationTrace 없음, D-W15-001).

### 사용하는 API
- `GET /sales/{saleId}/profit` (D-W15-005) — 매도건별 수익 조회(단건)
  - 응답 200: 수익 조회 성공
  - 응답 404: 매도건을 찾을 수 없음
- `GET /investors/{investorId}/profits` (D-W15-005) — 투자자별 수익 조회(목록+합계)
  - 응답 200: 수익 조회 성공
  - 응답 404: 투자자를 찾을 수 없음

### 조회 방식

| 조회 방식 | 설명 | API | 입력 필드 |
|-----------|------|-----|-----------|
| 매도건별 조회 | 특정 매도건의 수익을 단건 조회 | `GET /sales/{saleId}/profit` | saleId 입력 또는 드롭다운 선택 |
| 투자자별 조회 | 특정 투자자의 전체 수익 목록과 합계를 조회 | `GET /investors/{investorId}/profits` | investorId 입력 또는 드롭다운 선택 |

### 표시 항목 (D-W15-001: CalculationTrace 없음, API 응답 필드 그대로 표시)

| 필드명 | 설명 | 출처 |
|--------|------|------|
| saleAmount | 매도금액 | API 응답 |
| matchedAcquisitionAmount | 매칭된 취득가액 | API 응답 |
| matchedCostAmount | 매칭된 비용 | API 응답 |
| saleFee | 매도 수수료 | API 응답 |
| saleTax | 매도 세금 | API 응답 |
| saleOtherCost | 매도 기타비용 | API 응답 |
| preTaxProfit | 세전 수익 | API 응답 |
| afterTaxProfit | 세후 수익 | API 응답 |

- 위 8개 필드는 각각의 차감 항목 자체가 계산 근거이므로, 별도 "계산 이력 보기" 화면을 만들지 않는다(D-W15-001).
- 수익이 음수(손실)인 경우에도 동일한 필드를 표시하며, 금액에 음수 표시(빨간색 또는 마이너스 부호)를 적용한다.
- 투자자별 조회 시, 각 매도건의 수익 목록 외에 합계 행을 별도로 표시한다.

### 화면 상태

| 상태 | 설명 | UI 동작 |
|------|------|---------|
| 초기 (idle) | 화면 로드 시, 조회 입력 대기 상태 | 조회 폼만 표시, 결과 영역 숨김 |
| 로딩 (loading) | API 호출 중 | 결과 영역에 스피너 표시 |
| 성공 (success) | 200 응답 수신 | 수익 표시 테이블/카드가 채워짐 |
| 에러 (error) | 404/네트워크 오류 | 에러 메시지 표시 |

### 에러 처리 (D-W15-004: 락 충돌 UI 설계 금지)

| 에러 유형 | 필드 | 인라인 에러 메시지 |
|-----------|------|-------------------|
| 404 Not Found (매도건 미존재) | saleId | "해당 매도건을 찾을 수 없습니다." |
| 404 Not Found (투자자 미존재) | investorId | "투자자를 찾을 수 없습니다." |
| 400 Bad Request | 해당 필드 | API 응답의 에러 메시지를 매핑하여 표시 |
| 네트워크 오류 | 전체 화면 | "네트워크 연결을 확인해 주세요." |

### 수익이 음수(손실)인 경우
- 수익 필드(`preTaxProfit`, `afterTaxProfit`)가 음수인 경우, 빨간색 또는 마이너스 기호로 표시한다.
- 별도의 "손실" 표시를 추가하지 않고, API 응답 필드 값 그대로 표시한다(D-W15-001).

### 존재하지 않는 매도/투자자 조회 실패 케이스
- 존재하지 않는 `saleId`로 `GET /sales/{saleId}/profit` 호출 → 404 → "해당 매도건을 찾을 수 없습니다."
- 존재하지 않는 `investorId`로 `GET /investors/{investorId}/profits` 호출 → 404 → "투자자를 찾을 수 없습니다."

### 성공 후 이동 경로
- 수익 조회 완료 후, 동일 화면에 결과가 표시됨 (이동 불필요)
- 다른 화면으로 이동하려면 네비게이션 링크로 매도 등록 화면 또는 Epic 11 투자 내역 화면으로 이동 가능

## 4. 공통 섹션

### 4.1 매도 목록 별도 화면 없음 (D-W15-006)
- "매도 목록"은 별도 화면을 새로 만들지 않는다.
- Epic 11의 투자 내역 화면(`GET /investment-history`)이 이미 Subscription 기준으로 Allocation과 `sales[]`를 중첩 표시하므로, 매도 이력 확인은 그 화면을 재사용한다.
- 이 Epic은 **입력(매도/비용 등록)과 수익 확인(계산 결과 조회)**에만 집중한다.

### 4.2 매도 순서 (D-W15-003)
- 매도 순서는 `saleDate` 기준 정렬만 사용한다.
- 별도 순번 입력 필드를 만들지 않는다.
- 매도 등록 폼에 "순서 번호" 입력 필드가 없다.

### 4.3 수정/삭제 확인 다이얼로그
- **수정**: 모든 수정(PATCH) 동작 전에 확인 다이얼로그를 표시한다.
  - 내용: "정말로 이 항목을 수정하시겠습니까?" + 변경 전/후 값 요약
  - 확인/취소 버튼 제공
- **삭제**: 모든 삭제(DELETE, 논리 삭제) 동작 전에 확인 다이얼로그를 표시한다.
  - 내용: "정말로 이 항목을 삭제하시겠습니까? (논리 삭제됩니다)"
  - 확인/취소 버튼 제공
- **조사 결론 유지**: 확인 다이얼로그는 반드시 존재하며, 우회하지 않는다.

### 4.4 수정 이력 UI 없음 (D-W15-005 관련)
- 이 프로젝트에는 수정 이력을 표시하는 UI를 만들지 않는다.
- 백엔드에 별도 변경 이력 테이블이 없으므로 프론트에도 "수정 이력 보기" 같은 화면을 제공하지 않는다.
- 단순 수정 폼(현재 값을 불러와 덮어쓰기)만 제공한다.

### 4.5 접근성 기준 (WCAG 2.1 AA, D-W13-005)
- **기준**: WCAG 2.1 AA 준수
- **검증 도구**: `axe-core` 브라우저 확장/CI 통합 단일 채택
- **필수 요소**:
  - 모든 폼 필드에 `<label>` 요소 연결
  - 에러 메시지에 `aria-live="polite"` 속성 적용
  - 포커스 관리: 에러 발생 시 첫 번째 에러 필드로 자동 포커스
  - 색상만으로 에러를 전달하지 않음(아이콘/텍스트 병행)
  - 키보드 네비게이션 지원(Tab, Enter, Escape)
  - `aria-invalid` 및 `aria-describedby` 속성 사용

### 4.6 반응형 브레이크포인트 (D-W13-004)

| 브레이크포인트 | 최소 너비 | 적용 대상 |
|---------------|-----------|-----------|
| 모바일 | 640px | 폼 전체 폭 100%, 단일 컬럼 레이아웃 |
| 태블릿 | 768px | 2열 레이아웃 가능(필드 그룹화) |
| 데스크톱 | 1024px | 전체 폭 제한, 양쪽 여백 확보 |

- CSS 미디어 쿼리: `@media (min-width: 640px)`, `@media (min-width: 768px)`, `@media (min-width: 1024px)`
- 모바일 우선(mobile-first) 접근

## 5. 수용 기준 (Acceptance Criteria)

### AC-001: 매도 등록 성공
**Given** 유효한 allocationId, quantity, saleDate가 입력되고, 선택적 필드(price, amount, fee, tax, otherCost)가 유효한 값으로 입력됨  
**When** `POST /sales` 요청을 보냄  
**Then** 201 응답을 받음  
**And** 투자 내역 화면(Epic 11)으로 이동함  

### AC-002: 매도 등록 실패 (quantity 0 이하)
**Given** quantity가 0 이하인 값이 입력됨  
**When** `POST /sales` 요청을 시도함  
**Then** 서버 호출 전 프론트 유효성 검사가 실패함  
**And** "0 초과 정수를 입력해 주세요." 에러 메시지가 표시됨  

### AC-003: 매도 등록 실패 (음수 금액 필드)
**Given** price, amount, fee, tax, otherCost 중 하나 이상이 음수인 값이 입력됨  
**When** `POST /sales` 요청을 시도함  
**Then** 서버 호출 전 프론트 유효성 검사가 실패함  
**And** 해당 필드에 "0 이상의 정수를 입력해 주세요." 에러 메시지가 표시됨  

### AC-004: 매도 등록 실패 (404)
**Given** 존재하지 않는 allocationId가 입력됨  
**When** `POST /sales` 요청을 보냄  
**Then** 404 응답을 받음  
**And** "배정을 찾을 수 없습니다." 에러 메시지가 표시됨  

### AC-005: 매도 등록 실패 (409 충돌)
**Given** 서버가 409 Conflict를 반환하는 상황 발생  
**When** `POST /sales` 요청을 보냄  
**Then** 409 응답을 받음  
**And** 서버 응답 에러 메시지가 인라인으로 표시됨  
**And** 락 충돌 재시도 다이얼로그가 표시되지 않음 (D-W15-004)  

### AC-006: 매도 등록 실패 (누적매도수량>배정수량)
**Given** 누적 매도수량이 배정수량을 초과하는 quantity가 입력됨  
**When** `POST /sales` 요청을 보냄  
**Then** 400 응답을 받음  
**And** 서버 응답 메시지가 quantity 필드 아래 인라인 에러로 표시됨  
**And** 프론트에서 서버 검증 로직을 재구현하지 않음  

### AC-007: 매도 등록 실패 (서버 유효성 오류)
**Given** 서버가 거부하는 유효성 오류가 발생함  
**When** `POST /sales` 요청을 보냄  
**Then** 400 응답을 받음  
**And** API 응답의 에러 메시지가 인라인으로 표시됨  

### AC-008: 매도 등록 성공 후 이동
**Given** 매도 등록이 성공적으로 완료됨  
**When** 201 응답을 수신함  
**Then** 투자 내역 화면(Epic 11)으로 자동 이동함  
**And** 새로 등록된 매도가 목록에 saleDate 순으로 표시됨 (D-W15-003)  

### AC-009: 비용 등록 성공
**Given** 유효한 subscriptionId, costType, amount, incurredAt이 입력됨  
**When** `POST /costs` 요청을 보냄  
**Then** 201 응답을 받음  
**And** 비용 목록 화면으로 이동함  

### AC-010: 비용 등록 실패 (amount 0 이하)
**Given** amount가 0 이하인 값이 입력됨  
**When** `POST /costs` 요청을 시도함  
**Then** 서버 호출 전 프론트 유효성 검사가 실패함  
**And** "0 초과 정수를 입력해 주세요." 에러 메시지가 표시됨  

### AC-011: 비용 등록 실패 (404)
**Given** 존재하지 않는 subscriptionId가 입력됨  
**When** `POST /costs` 요청을 보냄  
**Then** 404 응답을 받음  
**And** "청약을 찾을 수 없습니다." 에러 메시지가 표시됨  

### AC-012: 비용 등록 실패 (서버 유효성 오류)
**Given** 서버가 거부하는 유효성 오류가 발생함  
**When** `POST /costs` 요청을 보냄  
**Then** 400 응답을 받음  
**And** API 응답의 에러 메시지가 인라인으로 표시됨  

### AC-013: 수익 조회 성공 (매도건별)
**Given** 존재하는 saleId가 입력됨  
**When** `GET /sales/{saleId}/profit` 요청을 보냄  
**Then** 200 응답을 받음  
**And** saleAmount, matchedAcquisitionAmount, matchedCostAmount, saleFee, saleTax, saleOtherCost, preTaxProfit, afterTaxProfit가 표시됨  

### AC-014: 수익 조회 성공 (투자자별)
**Given** 존재하는 investorId가 입력됨  
**When** `GET /investors/{investorId}/profits` 요청을 보냄  
**Then** 200 응답을 받음  
**And** 각 매도건의 수익 목록과 합계가 표시됨  
**And** 수익이 음수(손실)인 경우에도 금액이 올바르게 표시됨  

### AC-015: 수익 조회 실패 (존재하지 않는 매도건)
**Given** 존재하지 않는 saleId가 입력됨  
**When** `GET /sales/{saleId}/profit` 요청을 보냄  
**Then** 404 응답을 받음  
**And** "해당 매도건을 찾을 수 없습니다." 에러 메시지가 표시됨  

### AC-016: 수익 조회 실패 (존재하지 않는 투자자)
**Given** 존재하지 않는 investorId가 입력됨  
**When** `GET /investors/{investorId}/profits` 요청을 보냄  
**Then** 404 응답을 받음  
**And** "투자자를 찾을 수 없습니다." 에러 메시지가 표시됨  

### AC-017: 수익 조회에서 음수(손실) 표시
**Given** 수익 조회 결과에서 preTaxProfit 또는 afterTaxProfit가 음수임  
**When** 화면에 표시됨  
**Then** 빨간색 또는 마이너스 기호로 손실이 표시됨  
**And** API 응답 필드 값이 그대로 표시됨 (계산 근거 화면 없음, D-W15-001)  

### AC-018: 매도 등록 시 참고 표시
**Given** 매도 등록 화면에 진입함  
**When** 선택된 배정의 정보가 로드됨  
**Then** remainingQuantity가 읽기 전용으로 참고 표시됨  
**And** 사용자가 해당 값을 수정할 수 없음  

### AC-019: 매도 순서 (D-W15-003)
**Given** 매도가 여러 건 존재함  
**When** 투자 내역 화면에서 매도 목록을 확인함  
**Then** saleDate 기준으로 정렬되어 표시됨  
**And** 별도의 순번 필드가 존재하지 않음  

### AC-020: 접근성 검증 통과
**Given** 모든 화면이 렌더링됨  
**When** `axe-core`로 접근성 검사를 수행함  
**Then** WCAG 2.1 AA 기준을 통과함  
**And** `aria-live`, `aria-invalid`, `aria-describedby` 속성이 올바르게 적용됨  

### AC-021: 반응형 레이아웃
**Given** 다양한 화면 크기에서 화면이 렌더링됨  
**When** 브라우저 너비를 640px, 768px, 1024px로 변경함  
**Then** 각 브레이크포인트에 맞는 레이아웃이 적용됨  
**And** 모바일(640px)에서는 단일 컬럼, 태블릿(768px)에서는 2열, 데스크톱(1024px)에서 전체 레이아웃  

### AC-022: 네트워크 오류 처리
**Given** 네트워크 연결이 끊어진 상태  
**When** `POST /sales` 또는 `POST /costs` 요청을 보냄  
**Then** 네트워크 오류가 감지됨  
**And** "네트워크 연결을 확인해 주세요." 메시지가 표시됨  

### AC-023: 수정/삭제 확인 다이얼로그
**Given** 매도 또는 비용 항목의 수정/삭제 버튼을 클릭함  
**When** 버튼을 클릭하면  
**Then** 확인 다이얼로그가 표시됨  
**And** "정말로 수정/삭제하시겠습니까?" 내용이 포함됨  
**And** 확인을 누르지 않으면 수정/삭제가 수행되지 않음  

### AC-024: 수정 이력 UI 없음
**Given** 매도 또는 비용 항목을 수정함  
**When** 수정 완료 후  
**Then** "수정 이력" 화면이나 링크가 존재하지 않음  
**And** 단순 수정 폼(현재 값 덮어쓰기)만 제공됨  

### AC-025: 매도 목록 별도 화면 없음 (D-W15-006)
**Given** 매도 이력을 확인하고 싶음  
**When** 사용자가 매도 목록을 찾음  
**Then** 별도의 "매도 목록" 화면이 존재하지 않음  
**And** Epic 11의 투자 내역 화면에서 매도 이력을 확인함

## 6. E2E 테스트 범위

### 6.1 기본 플로우 (Happy Path)

#### 시나리오 1: 배정 → 매도 등록 → 비용 등록 → 수익 확인 전체 플로우
1. **배정 참고**: 투자 내역 화면(Epic 11)에서 특정 Subscription의 `remainingQuantity`를 확인
2. **매도 등록**: `POST /sales`에 유효한 allocationId, quantity, saleDate 및 선택적 필드 입력 → 201 응답 확인
3. **비용 등록**: `POST /costs`에 유효한 subscriptionId, costType, amount, incurredAt 입력 → 201 응답 확인
4. **수익 조회(단건)**: `GET /sales/{saleId}/profit` 호출 → 8개 필드가 올바르게 표시되는지 확인
5. **수익 조회(투자자별)**: `GET /investors/{investorId}/profits` 호출 → 수익 목록과 합계 표시 확인

#### 시나리오 2: 매도 등록 시 참고 표시
1. 매도 등록 화면 진입
2. 선택된 배정의 `remainingQuantity`가 읽기 전용으로 참고 표시되는지 확인
3. quantity 입력 시 remainingQuantity가 초과되지 않는지 UX 보조 확인

#### 시나리오 3: 투자자별 수익 조회에서 손실 표시
1. 투자자별 수익 조회(`GET /investors/{investorId}/profits`) 수행
2. 수익이 음수(손실)인 매도건이 존재하면 빨간색/마이너스로 표시되는지 확인

### 6.2 에러 케이스

#### 시나리오 4: 매도 등록 실패 (누적매도수량>배정수량)
1. 매도 등록 화면에서 quantity를 remainingQuantity보다 크게 입력
2. `POST /sales` 요청 → 400 응답 확인
3. 서버 응답 메시지가 quantity 필드 아래 인라인 에러로 표시되는지 확인
4. 프론트에서 서버 검증 로직을 재구현하지 않았는지 확인

#### 시나리오 5: 매도 등록 실패 (409 — 락 충돌 없음)
1. 매도 등록 시도 중 409 응답 발생
2. 서버 응답 메시지가 인라인으로 표시됨 확인
3. 락 충돌 재시도 다이얼로그가 표시되지 않는지 확인 (D-W15-004)

#### 시나리오 6: 매도 등록 실패 (404)
1. 존재하지 않는 allocationId로 `POST /sales` → 404 응답 확인
2. "배정을 찾을 수 없습니다." 메시지 표시 검증

#### 시나리오 7: 비용 등록 실패 (404)
1. 존재하지 않는 subscriptionId로 `POST /costs` → 404 응답 확인
2. "청약을 찾을 수 없습니다." 메시지 표시 검증

#### 시나리오 8: 수익 조회 실패 (매도건 미존재)
1. 존재하지 않는 saleId로 `GET /sales/{saleId}/profit` → 404 응답 확인
2. "해당 매도건을 찾을 수 없습니다." 메시지 표시 검증

#### 시나리오 9: 수익 조회 실패 (투자자 미존재)
1. 존재하지 않는 investorId로 `GET /investors/{investorId}/profits` → 404 응답 확인
2. "투자자를 찾을 수 없습니다." 메시지 표시 검증

#### 시나리오 10: 네트워크 오류
1. 네트워크를 차단한 상태에서 `POST /sales`, `POST /costs`, `GET /sales/{saleId}/profit`, `GET /investors/{investorId}/profits` 요청
2. "네트워크 연결을 확인해 주세요." 메시지 표시 검증

### 6.3 유효성 검증 테스트

#### 시나리오 11: 매도 등록 필드 유효성
1. quantity에 0 입력 → 서버 호출 전 차단됨 확인 (0 초과 필수)
2. price에 음수 입력 → 차단됨 확인 (0 이상)
3. fee/tax/otherCost에 음수 입력 → 차단됨 확인 (0 이상)
4. 선택적 필드를 비운 채 필수 필드만 입력하여 정상 등록 확인

#### 시나리오 12: 비용 등록 필드 유효성
1. amount에 0 입력 → 서버 호출 전 차단됨 확인 (0 초과 필수)
2. amount에 음수 입력 → 차단됨 확인
3. 선택적 필드(memo)를 비운 채 정상 등록 확인

#### 시나리오 13: 수익 조회에서 음수 손실 표시
1. 손실이 발생하는 매도건에 대해 수익 조회
2. `preTaxProfit` 또는 `afterTaxProfit`가 음수로 표시되는지 확인

### 6.4 확인 다이얼로그 테스트

#### 시나리오 14: 수정 확인 다이얼로그
1. 매도 또는 비용 항목의 수정 버튼 클릭
2. 확인 다이얼로그가 표시되는지 검증
3. 취소를 선택하면 수정이 수행되지 않는지 확인
4. 확인을 선택하면 수정이 적용되는지 확인

#### 시나리오 15: 삭제 확인 다이얼로그
1. 매도 또는 비용 항목의 삭제 버튼 클릭
2. 확인 다이얼로그가 표시되는지 검증
3. "논리 삭제" 내용이 포함되어 있는지 확인
4. 취소를 선택하면 삭제되지 않는지 확인

### 6.5 매도 순서 및 목록 재사용 테스트

#### 시나리오 16: 매도 순서 (D-W15-003)
1. 여러 매도가 등록된 후 투자 내역 화면에서 확인
2. 매도가 saleDate 기준으로 정렬되어 있는지 검증
3. 별도 순번 필드가 존재하지 않는지 확인

#### 시나리오 17: 매도 목록 별도 화면 없음 (D-W15-006)
1. 사용자가 "매도 목록"을 찾음
2. 별도의 매도 목록 화면이 존재하지 않는지 확인
3. Epic 11 투자 내역 화면에서 매도 이력을 확인할 수 있는지 검증

### 6.6 접근성 테스트

#### 시나리오 18: axe-core 접근성 검증
1. 매도 등록, 비용 등록, 수익 확인 화면 각각에서 `axe-core` 스캔 수행
2. WCAG 2.1 AA 위반 사항이 없는지 검증
3. `aria-live`, `aria-invalid`, `aria-describedby` 속성 올바른 적용 확인

### 6.7 반응형 테스트

#### 시나리오 19: 다양한 화면 크기
1. 640px(모바일), 768px(태블릿), 1024px(데스크톱)에서 각 화면 렌더링 확인
2. 레이아웃이 각 브레이크포인트에 맞게 적용되는지 검증

### 6.8 테스트 환경
- **테스트 도구**: Playwright (E2E)
