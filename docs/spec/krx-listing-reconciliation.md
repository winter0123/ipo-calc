# 스펙: KRX 추가상장 공고 기반 상장일·시초가 정합성 (krx-listing-reconciliation)

> 기준: research의 확인 사실. Phase 0 초안. Master 검토 후 breakdown에서 SF로 확정한다.

## 1. 사용자 목표

- 기존 DART 예정일과 KRX 확정 상장일을 구분해 표시한다.
- 과거 DART 예정일을 공식 KIND 추가상장 공고와 대조해 KRX 확정일로 보정한다.
- 수동 날짜 변경과 자동 보조 일정이 KRX 확정일을 덮지 않게 한다.
- 시초가 수집 대상을 KRX 확정일 기준으로 정리하고, 날짜/코드 변경 시 시초가를 무효화한다.
- UI 상세/목록에서 지난 DART 예정일을 완료로 오인하지 않게 한다.
- DART empty와 실패를 구분해 관측한다.
- 월별 집계에서 일반 상장월과 유상 청약월을 분리한다.

## 2. 승인 범위

승인된 범위:

1. 기존 날짜·시초가 정합성
2. 과거 DART 예정일 KIND 대조/확정
3. 화면 공통 표시
4. 동기화 조회 실패/공란 원인 분리

비범위:

- 운영 DB 직접 변경
- 배포, push, merge
- 자동 스크래핑/배치 자동화의 즉시 도입
- 추정 근접 매칭의 자동 승인
- KIND 공고 외 비공식 소스를 공식 근거로 사용
- 무상증자/전환/다른 발행 회차 처리
- IPO 행 합성
- raw HTML 저장

| FR-02 | 관리자 수동 날짜 변경 시 기존 `lastImportedListingDate`를 무효화하고, KRX 확정 상태가 아닌 경우에만 자동 정정을 허용한다. |

| FR-04 | 시초가 배치 대상은 KRX 확정 상장일(또는 명시적 수동 확정일)과 종목코드가 있는 행으로 제한한다. DART 예정일만 있는 행은 대상에서 제외한다. 레거시 null/eligible 행의 기존 수집은 유지한다. |
| FR-05 | UI 상세/목록은 동일 상태 규칙을 사용한다. 과거 DART 예정일을 자동으로 "상장 완료"로 표시하지 않는다. 출처 라벨을 함께 표시한다. |
| FR-06 | DART empty(`013`)와 실패(`020`, 인증, HTTP, null/parse)를 구분해 관측한다. 기존 typed convention을 재사용한다. |
| FR-07 | 월별 집계/필터는 일반 상장월과 유상 청약월을 별도 파라미터로 다룬다. |
| FR-08 | KIND 공고 입력은 공식 host와 허용 path만 사용한다. redirect를 차단하고 관리자 권한을 요구한다. |
| FR-09 | 운영자는 공고 URL/검색 조건으로 읽기 전용 미리보기를 실행한다. 서버는 공식 문서를 가져와 종목코드, 상장일, DART 실적보고서의 실제 발행주식수, 발행 사유, 발행 회차, 발행일을 추출한다. |
| FR-10 | 적용 전 동일 후보를 재검증한다. 종목코드·DART 실제 발행주식수·발행 사유·발행 회차가 모두 일치해야 한다. |
| FR-11 | KRX 발행일과 DART 납입일은 구분한다. 일치 여부가 아니라 보강 근거로 사용한다. |
| FR-12 | 적용 시 DART 원래 날짜/receipt를 보존하고, KRX 증거 참조 하나만 최소로 추가한다. |
| FR-13 | 적용은 멱등하다. 같은 공고/후보를 재적용해도 중복 변경이나 중복 기록이 생기지 않는다. |
| FR-14 | 동시 적용 요청은 직렬화하거나 충돌로 거절한다. |
| FR-15 | 무상증자, 전환, 다른 발행 회차, 다수 매치, 고유 증명 불가 후보는 적용 대상에서 거절하거나 review-only로 남긴다. |
| FR-16 | 기존 명시적 수동 편집은 사용자 작업으로 우선한다. 자동 갱신은 수동 값과 `CONFIRMED_KRX` 값을 보존한다. |

## 4. 데이터/상태 규칙

- 상장일 출처는 기존 `listing_date_evidence_type`을 그대로 사용한다: `ESTIMATED_DART`, `CONFIRMED_KRX`, null.
- null은 레거시/출처 불명 값을 의미하며 일괄 변경하지 않는다.
- KRX 확정일이 있으면 보조 일정과 수동 일정 보호 규칙보다 우선한다. 단, 수동 변경은 명시적 관리자 작업으로만 가능하며 근거를 남긴다.
- DART 원래 날짜는 `lastImportedListingDate` 등 기존 추적 필드로 보존한다.
- DART receipt는 기존 `listing_date_evidence_receipt`로 보존한다.
- KRX 증거는 별도 참조 하나만 최소로 추가한다. raw HTML은 저장하지 않는다.
- `listing_open_price`는 상장일 또는 종목코드가 바뀔 때만 null로 바꾼다. 같은 날짜 재적용에서는 보존한다.
- DB 스키마 결정은 SF2에서 최소화한다. migration 구현은 로컬 우선, 배포는 별도다.

## 9. 2026-11-24 후속 자동 대조 요구사항 (기존 PR #515)

- 관리자 클릭 없이 실행되는 기존 스케줄러 및 기본/월별 수동 동기화는 DART 저장·유상 발행실적 보완 이후 공통 `KrxListingAutoSyncService`를 호출한다. DART 동기화 중단 또는 발행실적 보완 `failures>0`에서는 KIND 적용을 실행하지 않는다. `reviewRequired>0` 자체는 조회 실패가 아니다.
- 70760 신규상장은 자동 수집 출처·14자리 최초 접수번호·종목코드·청약 종료 이후 매매개시일·수동 변경 부재를 확인하고 잠금 내 재검증 후 조건부 저장한다. 70791 추가상장은 DART 원문에 명시된 **같은 회차/발행일** 증거가 독립적으로 있어야 하며 수량·가격·납입일 근접만으로는 승인 금지.
- 동일 범위에서 유효한 추가상장 1건과 회차 근거가 불충분한 다른 공고가 함께 발견되면 **REVIEW_REQUIRED / 쓰기 0건**. 복수 유효 후보는 `ROUND_CONFLICT`; 검색 페이지 미완성·원문 불가·파싱 오류는 `FETCH_FAILED`; 전 페이지 정상 조회 시에만 `NO_NOTICE`.
- 기존 확정일/근거·수동 값·시초가를 보호하고 동일 요청 `NO_OP`, 날짜 변경 시 시초가 무효화, 다른 청약월 저장 금지를 유지한다. 운영 플래그 기본값은 `false`; 관리자는 미리보기/적용 예외 경로로 남는다.
- AC: 실제 동기화 진입점 회귀, 검색→뷰어→70760→PostgreSQL CAS, 보완 실패 차단, 유효 1/근거 미확인 1 보류, 취소·다른 회차·페이지 실패·경합·멱등·범위 밖 불변. 실서버 read-only 증명과 CI fixture 검증을 혼동하지 않는다.

## 자동 상장일 대조 추가 요구사항 (2026-11-24)

- 자동 적용이 **명시적으로 활성화된 경우에만**, 정상 종료된 DART 목록 동기화와 발행실적 보완 성공 이후 정기·수동 진입점에서 KIND를 실행한다. DART 보완 `failures > 0`이면 KIND 적용을 건너뛰며 `reviewRequired`만으로 건너뛰지는 않는다.
- 신규상장은 확인된 자동 수집 IPO 원신고·보통주 종목코드·청약 종료 후 상장일·수동 변경 부재가 필요하다. 추가상장은 DART와 KIND에 **독립적으로 명시된 동일 발행회차** 증거가 필요하다. 종목·날짜·수량·가격의 근접성만으로 승인하지 않는다.
- 한 검색 범위의 전체 페이지 성공, 공고별 뷰어·원문 파싱, 정정·취소 여부, 후보 유일성 확인 이후에만 조건부 저장한다. 복수 후보/근거 불충분/다른 회차/변경·취소/페이지 일부 실패는 저장 0건. 조회 실패는 `FETCH_FAILED`, 완결된 빈 조회만 `NO_NOTICE`.
- 조회 범위 밖 청약월 IPO를 변경하지 않는다. 같은 공고 재적용은 `ALREADY_APPLIED`; DART·관리자 수정과의 경합은 잠금·조건부 UPDATE로 막는다. 원문 HTML은 저장하지 않는다.
- 자동 호출 검증은 mock 관리자 HTTP가 아닌 실제 정기 진입점 → 합성 공식 검색·뷰어 → PostgreSQL CAS를 포함하며, 기존 관리자 미리보기·적용 계약을 유지한다.
