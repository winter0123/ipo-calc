# 계좌 관리 메뉴·폼 편집 흐름 spec (account-manage-edit-flow)

## 사용자 목표
증권사당 계좌관리를 정확히 1개 유지하면서, 미입력 계좌를 불필요하게 더 만들지 않고 기존 계좌를 채우거나 수정·삭제한다. 메뉴와 폼은 절대 동시에 보이지 않는다.

## 사용자 계약 (Acceptance Criteria)
- AC-1 증권사 카드당 "계좌관리" 토글은 정확히 1개다(기존 계약 유지).
- AC-2 미입력 상태 메뉴에는 계좌추가만 보인다. (수정·삭제 버튼 없음)
- AC-3 번호 입력된 계좌가 있는 메뉴에는 입력된 계좌별 수정 버튼과 회사 계좌추가 정확히 1개만 보인다.
- AC-4 삭제는 메뉴에서 제거되고 수정 폼의 삭제 버튼에만 있다. 삭제는 기존 ConfirmDialog로 확인하며 409(청약 이력, 취소 건 포함) 시 서버 메시지를 폼에 표시하고 폼을 유지한다.
- AC-5 번호 미입력 활성 계좌가 있을 때 계좌추가는 그 계좌(가장 오래된 것, id를 "미입력 #<id>"로 명시)를 채우는 폼(기존 id 편집)으로 연결된다. 새 미입력 계좌를 만들지 않는다.
- AC-6 번호 입력된 계좌만 있을 때 계좌추가는 새 계좌 생성 폼으로 연결된다.
- AC-7 메뉴와 폼은 하나의 state(View: idle/menu/create/edit)로 상호배타. 폼이 열린 상태에서 계좌관리를 다시 누르면 폼이 닫히고 메뉴로 전환된다. 다른 증권사의 계좌관리를 눌러도 열린 폼은 닫힌다.
- AC-8 저장/취소/삭제 후에는 폼과 메뉴가 모두 닫힌다(idle).
- AC-9 수정 폼의 기존 번호는 입력 기본값/서버값으로 마스킹 값을 쓰지 않는다. 기존 마스킹 안내 + 빈 새 번호 입력칸을 보여 준다. 10~16자리 입력은 기존 정규화(하이픈 포맷)·암호화·소유권·행 락 유지. 빈칸 저장 시 번호 무변경(PATCH에 accountNumber 미포함).
- AC-10 번호 변경(교체) 또는 최초 입력 저장 시 ConfirmDialog 경고를 거친다: "계좌번호가 바뀌어도 기존 청약·매도 이력은 같은 계좌에 남습니다. 증권사의 실제 계좌와 맞는지 확인해 주세요." 확인 전 PATCH 0회, 취소 시 입력 유지, 확인 후 PATCH 1회. 첫 번호 입력에도 동일 적용.
- AC-11 서버의 "기존 번호 존재 시 409" 교체 제한 제거(사용자 명시 승인). 같은 계좌 id·청약/매도 이력·브로커 연결은 유지된다. 번호 지우기(null)는 미지원(공백=400) 유지.
- AC-12 번호 미입력 채우기 폼도 기존 id 편집이므로 저장/취소/삭제 버튼을 동일하게 제공한다.

## 엣지 케이스
- 복수 미입력 계좌: 가장 오래된(createdAt, id) 하나를 채움 대상으로 선택.
- 번호 있는 계좌와 미입력 계좌 공존: 입력된 계좌별 수정 + 계좌추가(미입력 #id 표시) 노출.
- 확인 취소: 입력값 유지, PATCH 0회. 저장 재시도 시 확인 다이얼로그 재노출.
- 삭제 409: ConfirmDialog를 닫고 폼에 오류 표시(폼 유지, onDone 미호출).
- 생성 폼에는 삭제 버튼 없음. 번호 없는 생성은 기존처럼 optional.
